## Что нового для покупателя

**Корзина на несколько товаров.** Раньше каждая заявка была про один товар:
хочешь три — отправляешь три заявки, менеджер собирает их вручную. Теперь
техника складывается в корзину и уходит **одной заявкой**.

Корзина — это не оплата и не бронь, и приложение говорит об этом прямо:
«Наличие, комплектацию и итоговую стоимость подтвердит менеджер». Склад
корзиной не трогается.

- «Добавить» на карточке товара, после добавления — степпер `−  N  +`.
- Панель корзины над навигацией: сколько товаров, предварительная сумма, переход.
- Экран `/cart`: состав, актуальные цены, пометка «Цена обновилась», если цена
  изменилась после добавления, предупреждение о недоступных позициях.
- Оформление: имя, телефон, способ получения (самовывоз / доставка / уточнить),
  комментарий, согласие. Телефон обязателен, только если в Telegram ответить
  некуда.
- «Купить сейчас» на карточке товара добавляет только этот товар и открывает
  оформление — заявку не отправляет.
- Товар, которого нет: вместо кнопки, которая не сработает, — «Узнать о
  поступлении».

**Компактная главная.** До товаров стало на 170 px ближе: быстрые сценарии
свернулись из сетки 2×3 в одну строку, отступы верха уплотнены, крупные баннеры
теперь помещаются на экран по два.

## Что нового для менеджера

- Раздел «Заявки» — таблица: номер, тип, дата, клиент, телефон, Telegram,
  позиции, предварительная сумма, способ получения, статус, источник, менеджер.
- Детали заявки: состав со снапшотами **рядом с актуальными** ценами каталога и
  разницей; пометки «товар удалён» / «скрыт с витрины»; копирование состава в
  буфер; переход на товар витрины; диалог в Telegram.
- Статусы расширены: `Связались`, `Уточняем`, `Подтверждена` — рядом со старыми.
- История смен статуса (пишется в существующий журнал `audit_logs`).
- В карточке товара — «Доступность (корзина)»: `предзаказ`, `нет в наличии`,
  `под заказ`, `ограниченная партия`. Пусто = как раньше, из флагов наличия.

## Совместимость

- Существующие одиночные заявки работают без изменений и остаются в тех же
  списках, фильтрах и счётчиках.
- Миграция только добавляет: три таблицы, четыре колонки в `leads`, одна в
  `products`. Ничего не удаляется и не конвертируется.
- `products.availability_mode` по умолчанию NULL — поведение существующих
  товаров не меняется (проверено на проде: 0 строк с непустым значением).
- Новых переменных окружения релиз не требует.

## Для приёмки

- `/api/auth/admin/dev` — админ-вход без пароля **только при `DEV_MODE=true`**.
  В production маршрута нет (404), `ADMIN_PASSWORD` в нём не участвует, subject
  отдельный (`admin:dev@local`) — тестовые входы видно в журнале.
