# AI Seller — контекст проекта

Telegram Mini App магазин техники (Apple, Dyson, PlayStation) + бот + канал.

Этот файл читается автоматически в НАЧАЛЕ КАЖДОЙ СЕССИИ и потому стоит токенов
каждый раз. Здесь только то, что нужно всегда: адреса, деплой, самые дорогие
грабли и указатель, куда идти за остальным. Подробности — в `docs/context/`,
их читают по мере надобности.

**Правило пополнения:** новый факт идёт в `docs/context/*`, а сюда — максимум
одна строка-инвариант со ссылкой. Если строка не спасает от ошибки в ЛЮБОЙ
задаче, ей здесь не место.

## Деплой

```bash
bash update-server.sh
```

**Только из Git Bash.** Обычный `bash` в PATH уходит в WSL, а там нет SSH-алиаса
`iseller`. Из PowerShell — явным путём: `& "C:\Program Files\Git\bin\bash.exe"
update-server.sh`. Скрипт сам делает pg_dump в `/opt/backups`, синхронизирует
код, пересобирает стек и проверяет health. Серверный `.env` **не
перезаписывается** — новые переменные добавлять на сервере вручную.

Деплой синхронизирует ВСЁ рабочее дерево. Незакоммиченные правки уедут в прод —
перед деплоем убедись, что в дереве только то, что должно там быть.

**Деплой добавляет и заменяет, но НИКОГДА не удаляет.** Синхронизация — это
`tar x` поверх каталога, поэтому удалённый локально файл остаётся на сервере
навсегда. В сборку он не попадает, пока на него нет импорта (проверять надо
бандл, а не наличие файла), но `grep` по коду прода будет врать: удалённый
модуль там лежит как живой. Чистить — вручную по SSH.

Новые таблицы создаёт `Base.metadata.create_all` на старте; отдельная миграция
нужна только для колонок в СУЩЕСТВУЮЩИХ таблицах (мини-миграции в `main.py`).

## Telegram — здесь самые дорогие грабли

**Сеть VPS режет Telegram в обе стороны.** Хостер (HOSTKEY) подтвердил:
региональное ограничение, снимать не будут. Поэтому:

- исходящие идут через **Cloudflare WARP** → `TELEGRAM_PROXY_URL=socks5://172.18.0.1:40000`;
- WARP слушает только на `127.0.0.1`, до контейнера его дотягивает systemd-юнит
  `warp-docker-bridge` (socat на `172.18.0.1` — шлюз docker-сети
  `techshop_default`, из интернета недоступен). Пересоздание сети (`down`+`up`)
  может сменить подсеть — тогда правь юнит и `.env`;
- **вебхук не работает** — входящие до нас не доходят. Бот живёт на **long
  polling**, сервис `bot` в `docker-compose.prod.yml`;
- **экземпляр бота строго один.** Два параллельных `getUpdates` по одному токену
  Telegram отвергает с 409 Conflict;
- **в канале только `url`-кнопки.** `web_app`-кнопка отвергает ВЕСЬ пост
  (`BUTTON_TYPE_INVALID`), то есть он просто не публикуется. Обход — deep link
  `t.me/<bot>?start=<payload>`.

**Токен бота лежит в пути URL Bot API**, поэтому `httpx`/`httpcore` приглушены до
WARNING — иначе токен пишется в `docker logs` на каждое сообщение. Не поднимай
им уровень обратно.

## Навигация каталога — только из данных

**Списка категорий в коде нет и заводить его нельзя.** Он был захардкожен в
четырёх местах, разъехался с базой — и плитки «Dyson» и «Аксессуары» вели в
пустой каталог. Источник правды — сами товары, через `services/catalog_nav.py`:

| правило | где |
|---|---|
| категории = `SELECT DISTINCT category` по активным товарам | `list_categories()` |
| пустая категория не существует | там же, счётчик из товаров |
| плитка без товаров не выходит на главную | `has_products()` в `GET /home` |
| категория без плитки добавляется сама | слияние в `GET /home` |
| `is_active=False` у плитки — осознанное «скрыть», автодобавление не воскрешает | там же |

Незнакомая категория получает `FALLBACK_ICON` и подпись с заглавной буквы, но
**в навигацию попадает**. Добавлять её в код не нужно.

**Dyson — бренд, а не категория.** Его товары лежат в `красота` и `бытовая
техника`; плитка `action_type=category` физически не могла работать. Для таких
случаев `action_type=brand` → `/catalog?brand=Dyson`.

**Навигация двухосевая.** `GET /home` отдаёт `categories` и `brands`
(`list_brands()` — зеркало `list_categories()`). `action_type=brand` уходит на
ось брендов, остальное (включая непосчитаемые промо) — на ось категорий.
Правила видимости общие. На фронте тумблер осей общий с desktop-сайдбаром; при
пустом `brands` тумблера нет.

**Каталог по бренду показывает категории ЭТОГО бренда**
(`/catalog/categories?brand=`), со счётчиками этого же бренда. Глобальный ряд
предлагал «Смартфоны» на витрине Dyson, и тап давал пустой экран. Бренд живёт в
URL (`pickBrand`), чип с крестиком снимает его; смена бренда сбрасывает
категорию, снятие — сохраняет; брендовый ответ НЕ попадает в глобальный
localStorage-кэш (`lib/categoryCache.ts`).

## Порядок выдачи каталога

Правило живёт в ОДНОМ месте — `services/ranking.py`; им пользуются каталог,
`/catalog/feed`, поиск и рекомендации:

```
in_stock -> popularity -> позиция категории из плиток -> цена -> id
```

`popularity` пока нулевая у всех, и без добора `ORDER BY popularity DESC`
вырождается: Postgres отдаёт произвольный порядок, наверх выходит импортированное
первым (на проде так в «Популярном» стояли AirPods). Приор берётся из решения,
которое УЖЕ редактируется в админке — порядка плиток главной
(`home_categories.position`): нужно поднять Dyson — двигают плитку, а не код.

Что легко сломать обратно:

- **`id` в конце ключа обязателен** — иначе равные ключи снова дают произвольный
  порядок. Держит `test_order_is_fully_deterministic`;
- **категория без плитки уходит вниз, но НЕ пропадает** (`NO_TILE_RANK`);
- **явные сортировки (цена, рейтинг, hot) тоже дополнены этим порядком** — цена
  совпадает у десятков вариантов одной модели;
- `__sale__` и ось брендов в приор не попадают: у них свой разрез.

## Строка поиска: режима нет

Строка **всегда** ищет по каталогу, кнопка «✨ ИИ» внутри неё **всегда**
открывает `/ai` с набранным текстом (`auto=1`). Маршруты —
`lib/searchRoutes.ts`, одни на главную, каталог и desktop-шапку. Прежний тумблер
«Каталог / AI» только переключал режим и ничего не открывал — выглядело как
неработающая кнопка.

**Знака Claude в этой кнопке нет намеренно** — движок бывает и не Claude. Бейдж
живёт на экране AI, где сверен с `ai_vendor`.

## Грабли локального стенда (Windows + Docker)

- **Vite не видит правки через bind-mount** (inotify не работает): правил фронт
  — `docker compose -f docker-compose.demo.yml restart frontend`. Backend с
  `uvicorn --reload` подхватывает сам;
- **монтируется только `frontend/src`.** Правки в `tailwind.config.js`,
  `package.json` и прочем требуют `up -d --build frontend` — перезапуск и
  очистка кэша Vite не помогут.
