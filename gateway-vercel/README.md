# AI Gateway для AI Seller

Прозрачный прокси к Anthropic Messages API, живёт на Vercel.

## Зачем

`api.anthropic.com` отвечает `403 forbidden` с прод-VPS (`158.255.1.248`) —
региональное ограничение на стороне Anthropic. Проверено:

| откуда | ответ |
|---|---|
| прод напрямую | `403` |
| прод через WARP (`socks5://172.18.0.1:40000`) | `403` — выходной узел в том же регионе |
| локальная машина | `401` (нет ключа) — сеть и регион в порядке |
| Vercel | работает |

`403` наступает **до** проверки ключа, поэтому правильный ключ на проде ничего
не меняет. Нужна точка выхода в открытом регионе — ею и служит эта функция.

## Почему прокси, а не гейтвей со своим форматом

Сборка промпта и JSON-схема ответа живут в `backend/app/services/ai_anthropic.py`
и собираются из тех же `INTENTS`/`NEXT_ACTIONS`, что валидируют ответ. Копия
этой логики на JavaScript рано или поздно разъехалась бы с оригиналом — ровно
тот класс расхождения, из-за которого в проекте уже были мёртвые плитки.

Поэтому функция не знает ни про промпты, ни про схему, ни про модель: принимает
тело, подставляет ключ, возвращает ответ как есть, включая HTTP-статус. Вся
логика (structured outputs, повтор без схемы, обработка `refusal` и
`max_tokens`, ретраи SDK) остаётся в Python.

## Маршруты

| маршрут | назначение |
|---|---|
| `POST /api/v1/messages` | прокси к `https://api.anthropic.com/v1/messages` |
| `GET /api/health` | живость + факт наличия переменных (без значений) |

## Переменные окружения (задаются в Vercel)

| переменная | что это |
|---|---|
| `ANTHROPIC_API_KEY` | настоящий ключ Anthropic. Живёт **только здесь** |
| `GATEWAY_API_KEY` | общий секрет: его предъявляет backend в заголовке `x-api-key` |

На прод-VPS уезжает только `GATEWAY_API_KEY`. Компрометация прода не даёт
доступа к счёту Anthropic — секрет гейтвея отзывается сменой одной переменной.

## Подключение на стороне backend

```
AI_PROVIDER=anthropic
AI_ANTHROPIC_BASE_URL=https://<project>.vercel.app/api
AI_ANTHROPIC_API_KEY=<GATEWAY_API_KEY, не ключ Anthropic>
```

SDK сам добавляет `/v1/messages` к `base_url`. После правки `.env` контейнер
нужно **пересоздать** — `restart` не перечитывает `env_file`:

```bash
docker compose -f docker-compose.prod.yml up -d --build backend
```
