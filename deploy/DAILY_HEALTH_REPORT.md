# Мониторинг сервера: сводка раз в сутки и тревога в момент поломки

Два systemd-таймера на хосте, оба пишут админу (`ADMIN_TELEGRAM_ID`) в тот же
Telegram-бот. Задачи у них разные и подменять друг друга они не должны.

| | сводка | сторож |
|---|---|---|
| когда | 10:00 MSK, раз в сутки | каждые 2 минуты |
| зачем | «как дела вообще» | «что-то сломалось прямо сейчас» |
| пишет | всегда | только при смене состояния |
| звук | только если есть 🔴 | только тревога; отбой и напоминание — тихо |
| файл | `daily_health_report.py` | `health_watch.py` |
| юниты | `daily-health-report.{service,timer}` | `health-watch.{service,timer}` |

Проверки и пороги у обоих общие — `health_checks.py`. Две копии порогов
неизбежно разъехались бы, и сводка спорила бы с тревогой.

Скрипты живут на ХОСТЕ, а не в контейнере: половина проверок — диск, память и
статусы самих контейнеров, которых изнутри контейнера не видно. Пробрасывать
`docker.sock` внутрь ради этого нельзя — доступ к нему равносилен root на хосте.

Отправка идёт `curl`'ом через тот же SOCKS-прокси WARP, что и у бота: напрямую
Telegram с этого VPS недоступен.

## Два порога у каждой проверки

У `Check` два независимых флага:

* `bad` — красная строка в суточной сводке;
* `urgent` — повод написать немедленно.

Диск на 87% — `bad`, но не `urgent`: за сутки он не переполнится, а дёргать
человека незачем. Отсюда пары порогов в `health_checks.py`: диск 85 / 95%,
память 92 / 96%, нагрузка 2× / 3× от числа ядер. Ошибки бота в тревогу не
выносятся совсем (бот их переживает), кроме **409 Conflict** — он означает
второй запущенный экземпляр, и пока тот жив, сообщения покупателей теряются.

## Почему сторож не спамит

Вся логика — в чистой функции `decide()` (`health_watch.py`), и она же
покрыта тестами `backend/tests/test_health_watch.py`. Сбор цифр не тестируется:
там нет решений, только чтение.

| правило | константа | зачем |
|---|---|---|
| тревога с 2-й неудачи подряд, а не с 1-й | `CONFIRM = 2` | перезапуск контейнера и таймаут curl'а до человека не доезжают |
| пока проблема жива — ни одного повтора | — | иначе «API лежит» каждые две минуты |
| одна и та же проверка — не чаще раза в 30 мин | `COOLDOWN_SECONDS` | мигающая проверка не устраивает переписку «упало / поднялось» |
| напоминание, если всё ещё горит | `REMIND_SECONDS = 6 ч` | про сообщение, пришедшее ночью, легко забыть |
| отбой — только когда погасло ВСЁ | — | «одно из трёх починилось» не новость |
| отбой тоже требует 2 подтверждений | `CONFIRM` | иначе мигание давало бы пару сообщений вместо одной тревоги |

При таймере в 2 минуты авария доезжает за ~4 минуты.

**Состояние** лежит в `/var/lib/techshop/health_watch.json` и пишется через
временный файл: обрезанный на середине state означал бы «всё хорошо» и потерю
тревоги. Файл можно удалить — сторож начнёт с чистого листа (и напишет заново
о том, что сломано прямо сейчас).

## Пауза на время деплоя

`update-server.sh` пересобирает стек, и на минуту контейнеров действительно
нет — ровно та картина, на которую сторож обучен реагировать. Поэтому деплой
перед шагом 3 кладёт `/run/techshop-health.pause` с меткой «молчать до
now+15 мин», а после успешного health check убирает его. Файл в `/run`, так что
неудачный деплой не заглушит сторожа дольше, чем до перезагрузки.

Заглушить руками (например, на время работ):

```bash
ssh iseller "echo \$(( \$(date +%s) + 3600 )) > /run/techshop-health.pause"   # час тишины
ssh iseller "rm -f /run/techshop-health.pause"                                # снять
```

## Установка на новом сервере

Деплой кладёт только сами скрипты (они внутри рабочего дерева). Юниты systemd
лежат вне дерева, поэтому ставятся руками один раз:

```bash
scp deploy/daily-health-report.service deploy/daily-health-report.timer deploy/health-watch.service deploy/health-watch.timer iseller:/etc/systemd/system/
ssh iseller "systemctl daemon-reload && systemctl enable --now daily-health-report.timer health-watch.timer"
```

## Проверить руками

```bash
ssh iseller "python3 /opt/techshop/deploy/daily_health_report.py"
ssh iseller "python3 /opt/techshop/deploy/health_watch.py"
```

Расписание и последние запуски:

```bash
ssh iseller "systemctl list-timers daily-health-report.timer health-watch.timer --no-pager; journalctl -u health-watch --no-pager -n 20"
```

Проверить, что тревога реально дойдёт (обрывает WARP на минуту — Telegram у
бота на это время отвалится, сообщения покупателей встанут в очередь):

```bash
ssh iseller "systemctl stop warp-svc && sleep 300 && systemctl start warp-svc"
```
