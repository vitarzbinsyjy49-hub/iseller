# Известные ограничения демо (v2)

Осознанные упрощения, чтобы демо было стабильным и не раздутым. Ни одно из них не ломает ключевой сценарий.

## AI

- **По умолчанию AI не использует LLM.** `AI_PROVIDER=fallback` — ответы формируются правилами по каталогу (бюджет + категория). Это сделано намеренно, чтобы демо не зависело от Ollama/ключей. Реальный LLM включается `AI_PROVIDER=ai`.
- **Fallback-подбор простой.** Извлекает бюджет и категорию из текста и ищет по каталогу; он не «понимает» сложные сравнения так, как LLM. Для демо этого достаточно и выглядит убедительно.
- **Персонализация AI Engine выключена** (унаследовано): движок пишет историю, но не подстраивает ранжирование под пользователя. На сценарий не влияет.

## Каталог и данные

- **Картинки — placeholder** (dummyimage.com). Если внешний placeholder недоступен, фронтенд показывает эмодзи-заглушку и не ломается. Реальные фото заказчик добавит позже.
- **30 демо-товаров.** Достаточно, чтобы показать категории, фильтры и подбор; не полноценный каталог магазина.
- **Нет полноценной корзины.** Вместо неё — «Заявки» (Lead/CRM), что и требуется для демо-сценария.

## Инфраструктура

- **Таблицы создаются через `create_all`**, не через миграции Alembic. Для демо ок; для прод-эксплуатации нужен переход на миграции.
- **Ollama по умолчанию выключена** (профиль `ai`), т.к. модель тяжёлая (~5 ГБ). Включается отдельно.
- **Rate limit по умолчанию in-memory** (на процесс). Для нескольких инстансов backend нужен `RATE_LIMIT_REDIS_URL`.
- **Sync каталога в AI Engine — вручную** (одной командой/по кнопке). Cron/scheduler — задача прод-этапа.

## Безопасность

- Демо соблюдает минимум (ключи в .env, фронт не видит ключи, фронт не ходит в AI Engine напрямую, current_user валидируется, admin-эндпоинты защищены, CORS-guard, rate limit, max length, timeout, ORM, без dangerouslySetInnerHTML). Enterprise-меры (WAF, ротация секретов, аудит доступа) — вне рамок демо.
- **DEV_MODE=true открывает вход без Telegram** (`/auth/dev`). Это удобно для показа, но на проде обязательно `DEV_MODE=false`.

## Что заработает после вставки ключей

- Реальный Telegram-вход и открытие Mini App внутри Telegram — после `TELEGRAM_BOT_TOKEN` + Web App URL.
- LLM-ответы (осмысленные объяснения, сравнения) — после `AI_PROVIDER=ai` + Ollama (`OLLAMA_BASE_URL`) или облачного ключа (`OPENAI_API_KEY`).
- Персонализированный поиск — после доработки AI Engine (Sprint 2).

## Добавлено в v2

- **Motion — чистый CSS, а не framer-motion.** В среде сборки агента npm-реестр был недоступен, поэтому новые зависимости не добавлялись осознанно: вся плавность (page transitions, каскад карточек, bottom sheet, tap-scale, skeleton) реализована на CSS-keyframes. Это надёжнее для сборки и быстрее в рантайме.
- **Импорт товаров: sku хранится в `specs.sku`** — отдельной колонки нет. Матчинг при импорте: по `sku`, затем по точному `title` (без регистра).
- **Новые колонки Lead (`delivery_method`, `product_price`)** добавляются мини-миграцией `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` на старте backend — безопасно и для старой, и для свежей БД.
- **«Скидки» — виртуальная категория** (`__sale__`): фильтр `on_sale=true`, отдельной категории в БД нет.
- **DELETE товара в админке — мягкое отключение** (`is_active=false`), данные не удаляются.
- **История просмотров в профиле — заглушка** («Скоро»), событие `product_viewed` при этом пишется в аналитику.
- **Финальные фронтенд-сборки (`npm run build`) не выполнялись в среде агента** (реестр пакетов недоступен). Код написан без новых зависимостей поверх рабочей v1-сборки; перед показом прогоните `docker compose -f docker-compose.demo.yml up -d --build` и smoke-test локально.
