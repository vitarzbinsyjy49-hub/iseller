# Канал и прайс-посты

> Читать, когда работаешь с каналом `@isellerhub`, прайс-постами или
> инфо-постами. Инвариант в `CLAUDE.md`.

Канал `@isellerhub`, id `-1003998743702`, бот в нём администратор.

**Модель:** пост публикуется ОДИН раз и дальше редактируется на том же
`message_id`. У каждого раздела стабильный `slug` — он связывает раздел каталога
с конкретным сообщением. Потерять slug = потерять сообщение и выложить дубль.

| файл | ответственность |
|---|---|
| `services/price_posts.py` | чистая генерация текста и клавиатур, без сети и БД |
| `services/price_channel.py` | состояние: что опубликовано, что изменилось |
| `services/info_posts.py` | редактируемые посты (гарантия, доставка) + конструктор кнопок |
| `services/telegram_publisher.py` | отправка/правка, retry, 429 |
| `services/telegram_bot.py` | обработчики команд, `build_reply` без сети |

Источник прайса — **каталог в БД**, не XLSX: пост обязан совпадать с тем, что
покупатель видит в Mini App. XLSX — только для импорта.

Каждый пост фиксируется в БД сразу после успеха. Если пачка упрётся в лимит
Telegram на середине, уже полученные `message_id` уцелеют и повторный прогон не
создаст дублей.

Инфо-посты с маркером `[уточнить]` система публиковать отказывается — забытый
черновик в канале хуже отсутствия поста.

## Кнопки в канале

`web_app`-кнопки Telegram разрешает **только в личном чате с ботом**. В канале
сообщение с такой кнопкой отвергается ЦЕЛИКОМ (`BUTTON_TYPE_INVALID`) — то есть
пост просто не публикуется. В канале только `url`-кнопки: ведут на
`t.me/<bot>?start=<payload>`, бот ловит payload и открывает нужный экран Mini App
уже настоящей web_app-кнопкой.
