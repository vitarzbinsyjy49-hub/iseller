# Варианты товара: одна карточка на модель

> Читать, когда трогаешь выдачу каталога, карточку товара, импорт или
> жалобу «в каталоге сорок одинаковых айфонов». Инвариант — в `CLAUDE.md`.

## Зачем

Прайс BSA заводит товар на каждую комбинацию память × цвет × SIM × регион:
у iPhone 18 Pro это 40 позиций, у iMac M4 — 29. До 24.09.2026 каждая была
отдельной карточкой. Теперь:

- в каталоге, поиске и секциях главной — **одна карточка на модель + цвет**
  (решение владельца 24.09.2026): «iPhone 18 Pro Burgundy, от 130 000 ₽»,
  кнопка «Выбрать». Цвета одной модели стоят подряд. Память, SIM,
  конфигурация — внутри карточки. У линейки без цвета (Mac mini) карточка —
  модель целиком;
- на странице товара — ряды переключателей (цвет кружками, остальное
  кнопками), выбор уводит на соседний товар (`navigate(replace)`);
- регион — НЕ переключатель: из одинаковых по осям версий по умолчанию самая
  дешёвая, остальные — «другие версии (N)».

## Где что

| | |
|---|---|
| `services/family_rules.py` | правила по линейкам: товар -> модель + оси. Консервативны: не уверены — `None` |
| `services/variants.py` | `card_key` (модель + цвет), `collapse` (свёртка выдачи), `whole_family_info` (сводка по всем вариантам карточки), `variants_payload` (оси для страницы — по всей модели, цвет тоже переключается) |
| `products.family_key` / `products.variant` | «база» склейки. Сохранённое главнее правил |
| `scripts/backfill_families.py` | заполнить ПУСТЫЕ колонки по правилам (dry-run по умолчанию) |
| `import_bsa.upsert` | новая карточка сразу получает семейство |
| `frontend/src/lib/variants.ts` | выбор соседа (веса осей: цвет 8 > память/конфигурация 4 > связь 2 > SIM/комплектация 1) |
| `components/VariantPicker.tsx` | ряды из осей, «другие версии» |
| админка → товар | поля «Модель», «Оси варианта» (строки «Ось: значение»), «Продвижение» |

## Что склеивается (24.09.2026)

iPhone (оси: цвет, память, SIM), витринные образцы iPhone — своя модель
«… — витринный образец», iPad Pro/Air (цвет, память, связь), MacBook Air/Pro
и iMac (цвет, конфигурация), Mac mini/Studio (конфигурация), AirPods Max,
фены/стайлеры/выпрямители Dyson (цвет, комплектация), DualSense, Pulse,
Portal (цвет). Итог на проде: 42+3 модели, 405 товаров.

**Не склеиваются намеренно:** Apple Watch (размер, корпус и ремешок одной
строкой без разделителей), пылесосы Dyson (у каждой модели своя
комплектация), всё с «замен…», «ремонт», RFB, «[актив]». Слить два разных
товара хуже, чем не слить два одинаковых.

## Грабли

- **Свёртка — ДО среза по limit.** Иначе срез съедает места вариантами одной
  модели. Секции главной поэтому берут из базы 400 строк, а не 32: на 32
  строках 18-я серия занимала всю выборку «Горячего».
- **Сводка на карточке — по модели целиком** (`whole_family_info`), не по
  секции: «Горячее» содержит лишь часть вариантов, и «от X ₽» выходила выше
  настоящей.
- Ручная правка семейства в админке: пустое поле = «решают правила» (NULL),
  не модель с именем "". Иначе все очищенные товары склеились бы в одну.
- Новая линейка = новое правило в `family_rules` + тест на реальных
  названиях + `backfill_families` (он трогает только пустые колонки).

## Продвижение (`promo_boost`)

Ступень `services/ranking` между наличием и спросом. Нужна на запуск новой
модели: у неё нет просмотров, и честная популярность держала бы её под
прошлым поколением. Ставится скриптом (`launch_iphone18`) или в админке,
снимать — когда спрос наберётся сам. Просмотры НЕ накручивать: popularity
пересчитывается из реальных событий и накрутка затрётся.
