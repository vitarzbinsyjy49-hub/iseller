# Спека: PWA, установка за бонус, баннер на главной

> Решение от 14.09.2026. Читать вместе с `docs/context/cart-and-loyalty.md`
> (как устроены баллы) и `docs/superpowers/specs/2026-09-12-loyalty-rebuild-design.md`
> (почему у начисления есть потолок).

---

## 0. Зачем

Магазин живёт внутри Telegram Mini App. Это дёшево по дистрибуции, но у нас нет
ни иконки на экране человека, ни способа вернуть его иначе, чем через канал.
PWA даёт и то и другое: приложение ставится из браузера, без сторов, без
взносов и без ревью.

Чтобы установка случилась, за неё платим 500 баллов — по их же курсу это 500 ₽
скидки с первой покупки.

**Цена решения.** Списать можно не больше 5% чека (`redeem_max_bps`,
`cart.py:328`), значит 500 баллов уходят целиком на заказе от 10 000 ₽ — то
есть практически на любом нашем чеке. Маржа с чека ≈ 5 500 ₽, следовательно
установка стоит нам около **9% маржи одной сделки**, однократно на человека, и
только если он купит. Сгорание через 30 дней ограничивает обязательство по
времени и подталкивает к покупке, пока интерес не остыл.

---

## 1. Три вещи, которые ломают наивную реализацию

### 1.1. Установленное PWA не знает, кто в нём сидит

Авторизация идёт через Telegram: `initData` → проверка подписи
(`core/security.py:24`) → пара JWT, на которой дальше живёт фронт
(`lib/api.ts`). В установленном PWA Telegram отсутствует: нет SDK, нет
`initData`, нет подписи.

Без моста человек в установленном приложении — аноним. Он увидит каталог, но не
свой профиль, заявки, избранное и **не те самые 500 баллов**. Мы заплатили бы
за установку приложения, в котором нельзя потратить награду за установку.

Это главное требование спеки, а не деталь.

### 1.2. Из Telegram установить нельзя

Внутри WebView браузер не предлагает установку ни на одной платформе. Путь
обязан выходить наружу: Mini App → внешний браузер → установка там.

### 1.3. На iOS установка только руками

| | Android / десктоп | iOS |
|---|---|---|
| установка | кнопка, событие `beforeinstallprompt` | только Safari → «Поделиться» → «На экран Домой» |
| факт установки | ловится событием `appinstalled` | событий нет вообще |
| как узнаём | событие | **только когда приложение запустили** (`display-mode: standalone`) |

Отсюда: начисление привязано не к установке, а к **первому запуску**
установленного приложения. Это единственный сигнал, доступный на обеих
платформах.

### 1.4. Домен — блокер, а не улучшение

Установленное PWA привязано к origin. Переезд с `158.255.1.248.sslip.io` на
нормальный домен после запуска превращает все установленные приложения в
тыкву: другое хранилище, другой service worker, другая сессия. Переустановку
придётся просить вручную, а бонус уже выплачен и повторно не начислится.

Плюс `sslip.io` — чужой бесплатный сервис, и в диалоге установки такой адрес
выглядит как фишинг.

**Порядок работ: домен → переезд → PWA.** Ни одна строка PWA не выкатывается в
прод до переезда.

## 2. Решение: мост сессии одноразовым токеном

JWT у нас уже есть, поэтому отдельный «бонусный токен» не нужен — нужен
одноразовый обмен, после которого PWA живёт обычной сессией.

```
Mini App                     Внешний браузер              Установленное PWA
   │                               │                             │
   │ POST /pwa/install-token       │                             │
   │──────────────────────────────►│                             │
   │ ◄── {token}: user_id, TTL 48ч │                             │
   │                               │                             │
   │ tg.openLink(/install?t=TOKEN) │                             │
   │──────────────────────────────►│                             │
   │                     manifest: /api/pwa/manifest?t=TOKEN      │
   │                     start_url: /?pwa=TOKEN                   │
   │                               │                             │
   │                               │ установка ───────────────────►
   │                               │                             │
   │                         POST /pwa/installed {token} ◄────────│
   │                         ── JWT + 500 баллов ────────────────►│
```

**Токен запекается в `start_url` установленного приложения, а не в
`localStorage`.** Причина: на iOS у установленного PWA хранилище может быть
отделено от Safari, и `localStorage` перехода не переживёт. `start_url` —
часть самого приложения и работает всегда.

Первый запуск меняет токен на пару JWT и сохраняет её уже в своём хранилище.
Дальнейшие запуски идут обычным путём, токен в адресе к этому моменту мёртв.

### Отвергнутые варианты

- **Telegram Login Widget в PWA.** Честнее по идентификации, но требует
  настройки домена у BotFather, отдельного виджета и лишнего шага человеку —
  притом что в момент нажатия на баннер мы уже достоверно знаем, кто он.
  Держим в уме как запасной путь, если мост окажется дырявым.
- **Токен только в `localStorage`.** Проще, но ломается ровно на iOS, где у нас
  и так самый тяжёлый сценарий.

## 3. Начисление и сгорание

### Начисление

Вид транзакции `bonus` уже существует (`models/loyalty.py:38`). Уникальный
индекс `uq_loyalty_user_idempotency` по паре «пользователь + ключ» даёт «ровно
один раз за всю жизнь» даром: ключ `pwa_install`, повторная попытка упирается в
constraint и тихо ничего не делает.

Начисляем при `POST /pwa/installed`, когда сошлось всё: токен валиден, не
использован, и клиент сообщил, что запущен в `standalone`.

**Обмен сессии и начисление — одна транзакция, а не два вызова.** Разделённые,
они дают состояние «сессию выдали, баллы нет» при обрыве между ними, и второй
вызов уже не пройдёт: токен одноразовый и сгорел на первом. Либо человек
получает и сессию, и баллы, либо не получает ничего и может повторить.

### Сгорание через 30 дней

Срока годности у баллов в системе нет, и полноценный FIFO-учёт ради одного
бонуса заводить незачем. Правило без FIFO:

```
списано  = |SUM(points)| по транзакциям kind='spend' с created_at > <дата начисления>
остаток  = max(0, 500 − списано)
снять    = min(остаток, <текущий баланс>)
```

Считаем именно `spend` (списание в счёт покупки), а не любые отрицательные
строки: `correction` может быть и нашей собственной, и засчитывать её как
«человек потратил» значило бы прощать бонус за нашу же правку баланса.

Снимаем транзакцией `correction` с обязательным комментарием (его требует
`COMMENT_REQUIRED`). Ограничение текущим балансом обязательно: в минус баланс
уводить нельзя ни при каких обстоятельствах.

**Где это крутится.** Планировщика в проекте нет, но есть готовое место —
периодические сканы внутри цикла бота (`scripts/bot_polling.py:230`), где уже
живут напоминания о корзине и слежение за ценами. Добавляем
`loyalty_expiry.scan(db)` с суточным интервалом, по образцу соседей: отметка
времени двигается ПОСЛЕ успешного скана, итог пишется в лог всегда, ошибка не
имеет права уронить опрос апдейтов.

**Новая колонка — новая строка в `REQUIRED_SCHEMA`.** `expires_at` в
`loyalty_transactions` обязан попасть в проверку схемы там же
(`bot_polling.py`), иначе бот упадёт на `UndefinedColumn` при первом деплое —
эти грабли уже собирали.

## 4. Экран установки и баннер

### `/install` — публичная страница на домене

Определяет платформу и показывает ровно один путь, а не все сразу:

- **Android / десктоп:** кнопка «Установить», под ней — что человек получит.
  Работает через перехваченный `beforeinstallprompt`.
- **iOS:** три шага с картинками — «Поделиться» → «На экран Домой» →
  «Добавить». Честная подпись, что это займёт минуту.
- **Уже установлено** (`display-mode: standalone`): страница не уговаривает, а
  подтверждает — баллы начислены, вот они.

Страница работает и без токена: тогда это просто «поставьте приложение», без
обещания бонуса. Обещать награду тому, кого мы не сможем опознать, нельзя.

### Баннер на главной

**Признак «установлено» изнутри Mini App недоступен.** `display-mode:
standalone` там всегда ложь: Mini App и установленное PWA — разные контексты
браузера, и первый про второй не знает ничего. Спрашивать «а ты установил?»
у клиента бессмысленно.

Поэтому условие показа строится на единственном достоверном признаке —
**серверном**: получен ли уже бонус `pwa_install`. Он же и есть то, что мы
предлагаем, так что подмена признака честная: человеку, который бонус забрал,
предлагать нечего.

Показываем, когда сошлось всё:

| условие | откуда | почему
|---|---|---|
| бонус `pwa_install` ещё не начислен | сервер, в составе профиля | единственный надёжный признак |
| платформа поддерживается | клиент, user-agent | на неизвестной платформе обещать нечего |
| человек не закрывал баннер | `localStorage` | закрыл — значит ответил |

Крестик закрывает навсегда. Но предложение остаётся строкой в профиле —
передумавший должен иметь возможность вернуться.

**Это не баннер из админки.** `HomeBanner` приходит из `GET /home` и
редактируется в админке — он одинаков для всех. Наш зависит от состояния
конкретного человека и платформы, поэтому это отдельный компонент, который
рисуется в ленте промо, но живёт своей логикой. Смешивать их нельзя: иначе
условие показа расползётся между данными и кодом.

## 5. Безопасность

Токен в адресной строке — предъявительский ключ, обменивающийся на сессию.
Поэтому:

- **одноразовый** — второй обмен отклоняется;
- **TTL 48 часов** — достаточно, чтобы человек установил не сразу, и мало,
  чтобы утёкшая ссылка жила;
- **привязан к `user_id`** в момент выдачи, подменить адресата нельзя;
- **refresh-токен ротируется** при обмене;
- начисление идемпотентно по `pwa_install`, поэтому даже полностью успешная
  атака на токен не даёт повторных баллов — только доступ к чужому аккаунту,
  что уже покрыто TTL и одноразовостью.

## 6. Фазы

| фаза | что | зависит от |
|---|---|---|
| 0 | Домен: покупка, Caddy, сертификат, `MINI_APP_URL`, ссылки бота | владелец покупает домен |
| 1 | PWA как таковое: манифест, иконки, service worker, офлайн-каркас | фаза 0 |
| 2 | Мост сессии: `install-token`, динамический манифест, обмен, `/install` | фаза 1 |
| 3 | Бонус: начисление, сгорание, скан в боте, баннер и строка в профиле | фаза 2 |
| 4 | Web push: VAPID, подписки, статусы заявок в приложение | после запуска |

Фазы 1–3 выкатываются одним релизом: PWA без бонуса бессмысленно для
покупателя, бонус без PWA невозможен.

## 7. Чего не делаем

- **Магазины приложений.** App Store требует $99/год и ревью, с реальным риском
  отказа по гайдлайну 4.2 («просто упакованный сайт»). Chrome Web Store не
  вариант вовсе: Chrome Apps убраны в 2022, остались только расширения.
- **Офлайн-каталог.** Service worker кэширует каркас и статику, но не товары:
  цена и наличие — это ровно то, что нельзя показывать протухшим.
- **Общий срок годности для всех баллов.** `expires_at` вводится, но заполняется
  только у этого бонуса. Распространять на покупки — отдельное решение с
  отдельными последствиями для доверия.

## 8. Проверки

- `backend`: `python -m pytest -q` — правило сгорания (полное, частичное,
  нулевое списание; баланс не уходит в минус), идемпотентность начисления,
  одноразовость и TTL токена.
- `frontend`: `npx tsc --noEmit && npx vitest run && npm run build` — условия
  показа баннера, определение платформы, распознавание `standalone`.
- Живьём: установка на Android, установка на iPhone по инструкции, запуск
  установленного приложения, проверка что профиль и баллы на месте, повторный
  запуск (второго начисления нет).

Главное, что нельзя проверить на стенде и нужно проверить на устройствах:
**переживает ли токен переход из Safari в установленное приложение на iOS.**
Это центральное допущение всей конструкции — если оно неверно, запасной путь
Telegram Login Widget из раздела 2.
