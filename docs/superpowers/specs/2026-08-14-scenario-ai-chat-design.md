# Trade-In / Для бизнеса / Опт — AI-чат вместо форм

Дата: 2026-08-14

## Контекст

Сейчас Trade-In, Для бизнеса и Опт — три статичные bottom-sheet формы
(`frontend/src/components/ScenarioSheet.tsx` + конфиг в
`frontend/src/lib/scenario.ts`): chips + text + textarea, без диалога.
Открываются с Главной (кнопки `QuickScenarios`/квадраты `HomeTiles` в
`Home.tsx`). Итог — `POST /api/leads` с `lead_type ∈ {trade_in,b2b,wholesale}`
и `metadata` (структурированные ответы). Контракт и админка (`admin/src/ui.ts`
— `leadMetaRows`/`leadTitle`) уже читают эти поля универсально и добавлены
патчем v5.4.0 (`docs/SCENARIO_LEADS_AND_GALLERY.md`).

Отдельно есть настоящий AI-консультант `/ai` (`AiSearch.tsx` +
`services/ai_orchestrator.py`) — там уже есть детерминированное распознавание
намерений `trade_in`/`b2b`/`wholesale` по ключевым словам
(`_DETERMINISTIC` в `ai_orchestrator.py`), но оно просто показывает кнопку
«Написать менеджеру» — заявка не формируется.

**Задача:** заменить три статичные формы на диалог с ИИ, который ведёт сбор
той же структурированной заявки, точечно напоминает про УТП и доводит клиента
до кнопки «Отправить заявку», но не вызывает модель на каждую реплику —
экономия токенов через тот же паттерн, что уже есть в `ai_orchestrator.py`
(`_is_plain_browse`, детерминированные интенты): дешёвая ветка по умолчанию,
модель — только когда дешёвая ветка не справляется.

## Архитектура: скрипт ведёт, AI — по требованию

**Скрипт (клиент) — единственный источник переходов между шагами.** Конфиг —
расширенный `scenario.ts`: тот же список полей (chips/text/textarea), что и
сейчас у трёх сценариев, плюс:

- `intro` — вступительная реплика с УТП (см. раздел «Тексты» ниже), статика;
- у `chips`-полей — таблица синонимов для локального сопоставления свободного
  текста с вариантом (например `condition`: «треснул», «разбит», «скол» →
  `damaged`);
- `closingHook` — текст перед кнопкой отправки (сводка + короткое УТП),
  собирается шаблоном из уже введённых значений, без модели.

Тап по чипу = переход к следующему полю **без единого сетевого запроса**.
Свободный текст в text/textarea-поле принимается как есть (как сейчас в
`ScenarioSheet`) — там и раньше не было валидации, кроме «не пусто».

**AI подключается только в трёх случаях**, все — через один новый
backend-эндпоинт `POST /api/scenario-chat/turn`:

1. пользователь напечатал текст вместо тапа по chip-варианту, и локальный
   сопоставитель (синонимы) не смог его разрешить;
2. пользователь вместо ответа задал вопрос/возражение («сколько это будет
   стоить», «а гарантия есть») — распознаётся эвристикой (наличие `?`,
   вопросительные слова — тот же приём, что `_ABOUT_RE`/`_ADVICE_RE` в
   `ai_orchestrator.py`), модель отвечает **только из фиксированного
   FAQ-контекста** (см. «Тексты» ниже) и явно проинструктирована не
   изобретать цифры/сроки, которых там нет — та же дисциплина, что у
   `sanitize_money_claims` в `/ai/chat`;
3. никогда для финальной сводки — она собирается шаблоном на клиенте.

Если backend/модель недоступны (`AIGatewayError`, таймаут, `AI_FALLBACK`
выключен и упал транспорт) — деградация без блокировки: chips-поле просто
просит «Выберите один из вариантов ниже» (подсвечивает чипы), free-text поле
не зависит от AI вообще. Заявка **всегда** может быть отправлена, даже если
AI полностью недоступен — ядро флоу детерминировано.

## Компоненты

### Frontend

- Новый экран `frontend/src/pages/ScenarioChat.tsx`, маршрут
  `/apply/:scenario` (`scenario ∈ trade_in|b2b|wholesale`). Верстка в стиле
  `AiSearch.tsx` (пузыри реплик, chips как кнопки, typing-индикатор при
  ожидании AI-эскалации), но состояние — клиентский стейт-машин по шагам
  скрипта, а не серверный чат-контекст.
- `frontend/src/lib/scenarioChat.ts` — чистая логика (тестируется в vitest,
  без DOM, как сегодня `scenario.ts`/`scenario.test.ts`): текущий шаг →
  следующий шаг, локальный матчинг синонимов, сборка `metadata` для
  `POST /api/leads` (переиспользует `buildScenarioLead`-подобную функцию из
  `scenario.ts`), проверка «нужна ли AI-эскалация» (chip не совпал ИЛИ похоже
  на вопрос).
- `scenario.ts` расширяется полями `intro`/`closingHook`/синонимы у
  chips-опций. Существующие `ScenarioConfig`/`SCENARIOS` не переименовываются
  — `ScenarioSheet.tsx` и его текущие потребители могут быть безопасно
  удалены отдельным шагом после переключения точек входа (см. «Что
  удаляется»).
- Точки входа — везде, как решили в брейнсторминге:
  - `Home.tsx`: `openScenario(k)` вместо `setScenario(k)` (который открывал
    `ScenarioRequestSheet`) делает `navigate(\`/apply/${k}\`)`.
  - `AiSearch.tsx`/`ai/types.ts`: новый вариант `AiAction.type: "scenario"` с
    полем `scenario: ManagerRoleScenario` (`trade_in|b2b|wholesale`) —
    добавляется **рядом** с существующим `manager`, не вместо: пользователь,
    который явно просит менеджера текстом, всё ещё может получить прямую
    ссылку, но карточка ответа при интенте `trade_in/b2b/wholesale` получает
    ОБЕ кнопки («Оформить заявку» и «Написать менеджеру»), primary — заявка.
  - `ScenarioChoiceSheet` (меню выбора MacBook) **не трогаем** — это не
    lead-сценарий, а prefill в `/ai`.
- Отправка — существующий `POST /api/leads` (как в `LeadForm.tsx` сегодня),
  тот же контракт `{source, lead_type, phone, message, metadata}`. Экран
  успеха — тот же паттерн «Заявка отправлена» → «Посмотреть заявку»
  (`/requests`), что и в `ScenarioSheet` сейчас.

### Backend

- Новый эндпоинт `POST /api/scenario-chat/turn` (`backend/app/api/*`, новый
  файл `scenario_chat.py` рядом с `ai.py`). Вход:
  ```jsonc
  {
    "scenario": "trade_in",
    "field_key": "condition",
    "options": [{"value": "excellent", "label": "Отличное"}, ...],  // для chips-полей
    "message": "экран треснул, но включается"
  }
  ```
  Выход — одна из трёх форм (см. схему `ScenarioTurnAnswer` ниже):
  ```jsonc
  {"type": "field_value", "value": "damaged"}
  {"type": "answer_question", "reply": "Точную оценку даёт менеджер после осмотра — сроки и цену он назовёт после заявки."}
  {"type": "unclear", "reply": "Не понял ответ — выберите один из вариантов ниже."}
  ```
- `backend/app/services/ai_schemas.py`: новая pydantic-модель
  `ScenarioTurnAnswer` (`type: Literal["field_value","answer_question","unclear"]`,
  `value: str | None`, `reply: str | None = Field(max_length=300)`),
  свой `parse_scenario_turn(raw: str)` — переиспользует существующий
  JSON-repair (`_extract_first_object`/fence-strip) из `parse_structured_answer`.
- `backend/app/services/scenario_chat.py` — оркестратор по образцу
  `ai_orchestrator.answer_via_local_ai`, но короче:
  - `_sanitize()` входа (переиспользуется из `ai_orchestrator`);
  - для `field_value`: `value` обязан быть подмножеством переданных
    `options` (для chips) — модель не может подставить значение, которого не
    предлагали, то же правило, что «recommended_product_ids ⊆ candidates» в
    основном оркестраторе;
  - системный промпт — новый компактный файл
    `backend/app/prompts/scenario_chat_system.md`, содержит ТОЛЬКО текущее
    поле+варианты и фиксированный FAQ-блок (гарантия/самовывоз/оплата/
    доставка — раздел «Тексты»), явный запрет придумывать цифры/сроки вне
    этого блока;
  - тот же транспорт, что у `/ai/chat` (`ai_anthropic.call_anthropic` /
    `ai_remote.call_gateway` по `AI_PROVIDER`), тот же rate-limiter
    (`core/rate_limit.check_rate_limit`, тот же дневной/минутный лимит —
    отдельный лимит не заводим, это тот же AI-бюджет пользователя);
  - при `AIGatewayError`/`AiAnswerParseError`/недоступности — возвращает
    `{"type": "unclear", "reply": "Не расслышал — выберите вариант ниже."}`
    вместо 5xx: фронт обязан уметь продолжить без AI, эндпоинт никогда не
    роняет флоу заявки.
- **`Lead`, `POST /api/leads`, admin — не меняются.** `lead_type`/`metadata`
  контракт тот же, что и сегодня у `ScenarioSheet`.

### Что удаляется

После переключения точек входа и проверки в проде: в
`frontend/src/components/ScenarioSheet.tsx` удаляется только компонент
`ScenarioRequestSheet` (сама форма). `SheetShell` и `ScenarioChoiceSheet`
остаются в этом же файле как есть — `SheetShell` переиспользуется
`AiRoadmapSheet`/`LoyaltyRoadmapSheet`, а `ScenarioChoiceSheet` (меню
MacBook) вне скоупа этой задачи. Файл не удаляется целиком, только один
экспорт из него.

## Тексты (реальные факты проекта, не выдумка)

Источники: `backend/app/services/info_posts.py` (живые тексты постов канала),
`docs/context/cart-and-loyalty.md`, `docs/context/channel-posts.md`.

- **Гарантия 1 месяц** с момента покупки на всю технику из прайса (та же
  формулировка, что в `info_warranty` — важно не заводить вторую версию
  одного факта, это уже было багом: «14 дней» в коде против «1 месяц» в
  карточке, см. `docs/superpowers/plans/2026-08-07-prelaunch-1-channel-and-warranty.md`).
- **Проверка при клиенте** до оплаты (включаем устройство вместе, смотрим
  внешний вид и работу основных функций).
- **Самовывоз — Горбушка, Москва, ежедневно 10:00–21:00** — можно забрать в
  день обращения, без записи за дни вперёд.
- **Доставка по Москве курьером.**
- **Оплата наличными при получении** — на самовывозе после проверки, при
  доставке курьеру.

FAQ-блок для AI-эскалации (раздел «backend») собирается из ЭТИХ фактов
буквально — LLM не должна их переформулировать в сторону более сильных
обещаний (сроки/суммы).

### `intro`/`closingHook` по сценариям

- **Trade-In** — intro: «Оценим вашу технику и предложим обмен на новое или
  выкуп. Самовывоз в Москве ежедневно 10:00–21:00, оценка и расчёт — при
  проверке устройства.» closingHook: «Заявку рассмотрит trade-in менеджер,
  обычно в течение дня.»
- **Для бизнеса** — intro: «Подберём поставку под компанию: смартфоны,
  ноутбуки, техника для сотрудников. Документы для юрлиц, оплата по счёту
  обсуждается с менеджером.» closingHook: «Заявку рассмотрит B2B-менеджер и
  пришлёт предложение под ваш объём.»
- **Опт** — intro: «Назовите категорию и объём партии — посчитаем оптовую
  цену.» closingHook: «Заявку рассмотрит оптовый менеджер и пришлёт цену под
  партию.»

Сроков («в течение часа», «завтра») не даём нигде, кроме уже проверенного
факта самовывоза день в день — по тому же правилу, что и в роудмапах AI/
лояльности (`docs/context/ai.md`, `docs/context/cart-and-loyalty.md`): дата —
это обещание, а обеспечить его в тексте некому.

## Данные и state

Backend — **полностью stateless** между шагами, как и сегодня `/ai/chat`:
эндпоинт получает только текущее поле + текст, ничего не хранит про сессию
диалога. Вся история шагов и собранные ответы живут в состоянии React-экрана
и пропадают при уходе с экрана без отправки — то же поведение, что у
`ScenarioSheet` сегодня (закрыл шторку — прогресс потерян). Персистентность
между перезапусками приложения — вне скоупа, не запрашивалась.

## Обработка ошибок

- Backend недоступен/rate-limit исчерпан → `{"type":"unclear", "reply": "..."}`
  либо (для сетевых сбоев без ответа вовсе, как в `AiSearch.submit`) фронт сам
  трактует таймаут/сеть как `unclear` — код уже есть на фронте как паттерн
  (`AiSearch.tsx` `catch` → fallback), переиспользуем его форму.
- LLM вернула `value`, которого не было в `options` (chips) → отбрасывается,
  трактуется как `unclear` — то же правило, что «recommended_product_ids вне
  кандидатов» в основном оркестраторе.
- Заявка (`POST /api/leads`) падает — тот же UI ошибки/retry, что уже есть в
  `ScenarioSheet` (error state, повторная отправка, защита от даблклика).

## Тестирование

**Frontend** (`frontend/src/lib/scenarioChat.test.ts`, vitest, без DOM):
переходы между шагами, локальный матчинг синонимов (положительные и
отрицательные кейсы), сборка `metadata`/`message` для отправки — идентично
подходу `scenario.test.ts` сегодня.

**Backend** (`backend/tests/test_scenario_chat.py`, по образцу
`test_ai_orchestrator.py`):

- `parse_scenario_turn`: валидный JSON, JSON во fence, битый JSON →
  `AiAnswerParseError`;
- `value` вне переданных `options` → отбрасывается как `unclear`;
- gateway недоступен (замоканный `AIGatewayError`) → `unclear`, без 5xx;
- rate-limit исчерпан → `unclear`, без 429 (тот же принцип, что дневной
  лимит `/ai/chat` — тихая деградация, не отказ);
- FAQ-эскалация не может исказить факты — тест на промпт/структуру запроса
  (что FAQ-блок в system-промпте содержит ровно зафиксированные факты, без
  runtime-переменных, которые могли бы разъехаться с `info_posts.py`).

`Lead`/`POST /api/leads`/admin — уже покрыты `test_leads_scenario.py`,
дополнительных тестов не требуют (контракт не меняется).
