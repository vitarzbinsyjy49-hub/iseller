# Цены: история, режим администратора в Mini App, сверка с источниками

Утверждено владельцем 07.10.2026. Повод: MacBook Air 15 `MDVH4` стоял 120 000 при
цене BSA 133 000 — сверка BSA находила только карточки, которые сама завела
(по артикулу), а ~250 карточек из «Импорта» не видела вовсе.

## Этап 1 (этот релиз)

### История цен
- Таблица `price_changes`: product_id, old_price, new_price, source, actor, note, created_at.
- Пишется **одним** слушателем SQLAlchemy `before_flush` на любое изменение
  `Product.price` — из админки сайта, импорта, скриптов, Mini App. Отдельного
  вызова «не забыть записать историю» нет, поэтому её нельзя обойти.
- Кто и откуда — из `session.info["price_actor" | "price_source"]`; по умолчанию
  `system` / `unknown`.

### Вход администратора в Mini App
1. Список админов — `ADMIN_TELEGRAM_IDS` в серверном `.env` (через запятую;
   если пусто — `ADMIN_TELEGRAM_ID`). В базе и интерфейсе его нет.
2. Mini App с обычным пользовательским токеном (выдан по подписи initData) зовёт
   `POST /api/staff/login`. Сервер проверяет, что telegram_id в списке, создаёт
   заявку на 5 минут со случайным nonce и шлёт в чат бота сообщение с
   url-кнопкой `t.me/<бот>?start=staffok_<nonce>`.
3. Нажатие кнопки = сообщение `/start staffok_<nonce>` от того же аккаунта.
   Бот (long polling, без callback_query — см. telegram_bot.py) подтверждает
   заявку, только если отправитель совпадает с автором заявки.
4. Mini App опрашивает `GET /api/staff/login/{id}` и получает staff-токен
   (`sub=staff:<tg_id>`, тип `staff`, 2 часа). Токен — в sessionStorage, к
   обычным API не подходит; пользовательский токен не подходит к staff API.
5. Каждый запрос staff API заново проверяет, что id всё ещё в списке.
6. Попытка входа не-админа: 403 + сообщение владельцу.
- ИИ-консультант бота не получает инструментов записи — prompt injection
  «я админ, поменяй цену» физически не на что направить.

### Staff API (`/api/staff/*`)
- `GET /eligible` — может ли текущий пользователь стать админом (для показа строки в профиле).
- `GET /products?q=&filter=` — список: цена, наличие, дата последнего изменения.
- `PATCH /products/{id}` — цена и/или наличие. Изменение цены > 30% требует
  `confirm=true` (иначе 409 `need_confirm`). Цена 1…50 000 000.
- `GET /products/{id}/history`, `POST /products/{id}/revert/{change_id}`.
- Всё пишется в `audit_logs` с actor `tg:<id>`.

### Экраны Mini App
- Профиль: строка «Режим администратора» (только для `eligible`).
- `/staff` — вход с подтверждением в боте.
- `/staff/prices` (вариант A): поиск, фильтры, правка цены на месте, ±500.
- Карточка товара (вариант C): у админа кнопка «Правка» → шторка: цена,
  наличие, история, откат.

## Этап 2 (следующий)
- Сборщик источников: служебный Telegram-аккаунт (Telethon ≥1.45 понимает
  RichMessage — посты iPhone у BSA) читает BSA и apostl price раз в час через
  WARP. Резерв — `result.json` боту и публичный виджет t.me для не-rich постов.
- Привязки карточка ↔ ключ строки (артикул Apple / ключ iPhone / нормализованное
  название+регион), засев из `bsa_links_2026_10_06.tsv`.
- Правило цены на карточке: apostl (если есть) → иначе BSA−500 → «вручную».
- Автоприменение ≤10%, остальное — очередь «Проверить» (вариант B), сводка в бот,
  отчёт о ценах, не подтверждённых источником > 7 дней.
