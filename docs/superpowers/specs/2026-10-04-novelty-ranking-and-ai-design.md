# Умный рейтинг: новинки впереди + ИИ знает про новинки + вопрос в карточке

Дата: 2026-10-04. Решение владельца: «новизна» — автоматически, по дате первого
появления МОДЕЛИ в админке (вариант A). Делаем три части сразу.

## Почему

На проде 04.10 на «что нового из телефонов» ИИ назвал iPhone 17 «текущим
флагманом» при 64 iPhone 18 в наличии. Три ручки «новизны» не работают:

| ручка | состояние |
|---|---|
| `is_new` | ставится руками и никогда не снимается: 307 из 488 товаров, включая 200 из стартового импорта 20.07 — флаг ничего не значит |
| `promo_boost` | работает, но только у 64 iPhone 18 из скрипта запуска; зависит от того, не забудут ли поставить и снять |
| `popularity` | `scripts/recompute_popularity.py` есть, но его никто не запускает — ни таймера, ни цикла. 298 просмотров за 90 дней лежат без пользы |

## Часть 1. Новизна в рейтинге (backend + admin)

### Определение

**Новинка — модель, которая впервые появилась в каталоге не раньше
`NOVELTY_WINDOW_DAYS` (45) дней назад.**

- «Модель» = `family_key`. Новый цвет iPhone 17 не делает его новинкой, первый
  iPhone 18 делает. Товар без `family_key` — сам себе модель.
- «Впервые появилась» = `min(created_at)` по всем товарам модели, ВКЛЮЧАЯ
  неактивные (снятый и вернувшийся вариант не делает модель новой).
- Дата хранится в новой колонке `products.model_first_seen_at` (timestamptz,
  nullable, индекс). Все варианты модели несут одно и то же значение.
- `is_new` перестаёт быть ручным: его выставляет система,
  `is_new = model_first_seen_at >= now() - window`. Ручное продвижение старого
  товара — `promo_boost` (уже есть в админке).

### Сервис `services/novelty.py`

- `NOVELTY_WINDOW_DAYS` — из `settings` (по умолчанию 45).
- `novelty_cutoff(now=None) -> datetime`.
- `sync_novelty(db, family_keys: set[str] | None = None) -> int` — пересчитывает
  `model_first_seen_at` и `is_new` для всех товаров (или только для указанных
  моделей), возвращает число изменённых строк. Идемпотентна.
- `is_fresh(product, now=None) -> bool` — для Python-кода.

Кто вызывает `sync_novelty`:
1. старт backend (`main.py`, после мини-миграций) — бэкфилл и выравнивание;
2. цикл бота (`scripts/bot_polling.py`, по образцу `_due(...)`) — раз в час:
   окно сдвигается со временем, и `is_new` должен гаснуть сам;
3. создание/правка товара в админке и импорт — для затронутых моделей
   (`family_key` товара).

### Порядок выдачи (`services/ranking.py`)

Новая ступень между `promo_boost` и `popularity`:

```
legendary -> preorder -> in_stock -> promo_boost -> НОВИЗНА -> popularity -> категория -> цена -> id
```

НОВИЗНА: свежие модели выше несвежих; среди свежих — более новая выше; у
несвежих ступень одинаковая (решение уходит в popularity).

- SQL: `case((model_first_seen_at >= cutoff, model_first_seen_at), else_=None).desc().nulls_last()`.
- Python (`product_sort_key`): тот же смысл, `-timestamp` для свежих, `+inf`-эквивалент для остальных.
- Тест держит совпадение SQL- и Python-порядка на одном наборе.
- Обновить docstring модуля и раздел «Порядок выдачи» в `CLAUDE.md` (одна
  строка ключа).

### Популярность начинает жить

Цикл бота раз в сутки вызывает ту же логику, что `scripts/recompute_popularity.py`
(вынести тело в функцию `recompute_popularity(db) -> int`, скрипт остаётся
тонкой обёрткой).

### Админка

- Колонку/чекбокс «Новинка» в форме товара заменить read-only подписью:
  «Новинка до 18.11» / «Не новинка (модель с 11.08)». Отправку `is_new` из
  формы убрать; backend игнорирует `is_new` из тела запроса (не ломается, если
  придёт).
- Подсказка у `promo_boost`: «поднять старый товар — сюда».

### Миграция

- `ALTER TABLE products ADD COLUMN IF NOT EXISTS model_first_seen_at TIMESTAMPTZ`
  + индекс — мини-миграция в `main.py`.
- Колонку добавить в `REQUIRED_SCHEMA` в `scripts/bot_polling.py` (иначе бот
  падает `UndefinedColumn` на деплое — грабли 24.09).
- Бэкфилл делает `sync_novelty` на старте; отдельный скрипт не нужен.

## Часть 2. ИИ знает про новинки

1. `extract_filters`: флаг `prefer_new`, если в запросе есть «нов», «новинк»,
   «последн», «свеж», «вышл», «вышед», «2026», «latest», «new». С границей слова
   там, где корень короткий («нов» не должен ловить «Новосибирск» — тест).
2. `retrieve_candidates`: при `prefer_new` структурная ветка сортируется по
   новизне первой, и в `_score` свежая модель получает бонус. Бонус свежести
   есть и без `prefer_new` (меньше), чтобы при равной релевантности «айфон»
   давал iPhone 18 раньше 17. Релевантность остаётся первым ключом (фикс e69f327).
3. `candidate_payload`: поле `is_new` (bool) и `model_since` (ISO-дата).
4. Промпт (`prompts/ai_seller_system_v2.md`, активная версия — проверить
   `AI_SYSTEM_PROMPT_VERSION`): «`is_new=true` — самые новые модели магазина.
   На вопросы о новинках/последней модели называй их. Никогда не утверждай,
   что модель не вышла или её нет, если она есть среди кандидатов».
5. Быстрый путь `_is_plain_browse` / `build_demo_answer`: «новинки» и
   «что нового» отдают свежие модели (порядок из ranking уже даёт это — проверить
   тестом).

Регрессионный тест: каталог с iPhone 17 (старый, популярный) и iPhone 18
(свежий, нулевая популярность) — «что нового из телефонов» и «какой последний
айфон» дают iPhone 18 первым в кандидатах.

## Часть 3. Вопрос прямо в карточке товара (роудмап `ai-in-card`, октябрь)

Сейчас «Спросить AI» уводит на `/ai?product=<id>`. Делаем ответ рядом с товаром.

- Блок в `ProductDetails.tsx` под ценой/кнопками: заголовок «Спросить про этот
  товар», 3 чипа-вопроса и поле ввода. Чипы: «Чем отличается от прошлой
  модели?», «Что есть новее или похожее?», «Кому подойдёт?».
- Запрос — существующий `POST /api/ai/chat` с `product_id` (пайплайн
  `FOCUS_PRODUCT` + `alternatives_for` уже есть, backend не меняется).
- Ответ рендерится inline тем же форматом, что в чате (`lib/answerFormat.ts`,
  компоненты из `components/ai/`), карточки — компактным рядом.
- Под ответом «Продолжить в чате →» ведёт на `/ai?product=<id>` (история
  одного ответа не переносится — YAGNI).
- Состояния: загрузка (скелетон), ошибка/лимит (`429`) — короткий текст и
  «Попробовать ещё раз». Без ответа — блок компактный, не толкает контент.
- Аналитика: `track("ai_in_card_ask", {product_id, preset|custom})`.
- Не показывать на легендарном товаре (`LegendaryProduct` — своя кнопка) и на
  предзаказе (ИИ предзаказы не видит).
- Анимация — только через существующий motion-слой (`lib/motion.ts`),
  CSS-анимации этот webview гасит.
- `roadmap.ts`: пункту `ai-in-card` — `done: true` с комментарием даты.
