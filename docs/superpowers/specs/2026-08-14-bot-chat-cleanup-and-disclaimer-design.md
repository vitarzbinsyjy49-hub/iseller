# Чистый чат бота + юридический дисклеймер в приветствии

Дата: 2026-08-14

## Контекст

В `backend/app/services/telegram_bot.py` уже есть незакоммиченный мини-фикс:
`Reply.is_redirect` — при клике по кнопке канала (`t.me/<bot>?start=<payload>`)
бот перед отправкой нового ответа удаляет своё предыдущее сообщение-редирект
в этом чате, чтобы повторные клики не копили одинаковые карточки.

Осталось два пробела:

1. **Входящее сообщение пользователя не удаляется.** `/start price_iphone`,
   которое Telegram сам отправляет от имени человека при переходе по deep
   link, остаётся в чате навсегда — именно это видно на скриншоте (несколько
   `/start` подряд от 13–14 августа).
2. **Правило «одно сообщение вместо накопления» действует только для
   редиректов**, а не для обычных команд (`/catalog`, `/ai`, `/orders`,
   `/manager`, `/prices`, произвольный текст) — там ответы бота копятся так же,
   как раньше копились редиректы.

Отдельно: нужен информационный блок в приветствии бота, снимающий один
конкретный юридический риск (см. раздел 3).

Полный переход на `startapp=` (открытие Mini App без захода в чат бота вообще,
как у `t.me/DTMcatalog_bot/?startapp=...`) **в этот патч не входит** — см.
раздел 4.

## 1. Обобщение «одно сообщение вместо накопления»

Правило переносится с редиректов на **все** ответы, которые уходят через
`send_reply`:

- у бота в чате в любой момент не больше одного его собственного сообщения,
  отправленного через `send_reply` — новое всегда заменяет предыдущее
  (удаление старого + отправка нового);
- входящее сообщение пользователя, вызвавшее ответ (`/start`, `/catalog`,
  `/ai`, `/orders`, `/manager`, `/prices`, произвольный текст), удаляется
  сразу же.

`Reply.is_redirect` как отдельный флаг убирается — это поведение становится
поведением по умолчанию для любого `Reply`, возвращённого `build_reply`.

**Что этот механизм НЕ трогает:** уведомления (`services/notifications.py` —
падение цены, неоплаченная корзина) и посты канала (`price_posts.py`,
`info_posts.py`) отправляются отдельными функциями `telegram_publisher`,
никогда не проходят через `send_reply`/`build_reply` — значит физически не
могут быть задеты этим изменением. Это и есть требуемое разделение: команды
чистятся, история уведомлений остаётся навсегда.

### Архитектура

`build_reply(update)` остаётся чистой функцией без сети — она не должна
приобретать побочных эффектов. `message_id` входящего сообщения нужен только
`send_reply`, и он уже доступен в обоих местах, где вызывается
`build_reply`/`send_reply` (`bot_polling.py`, `api/telegram.py`), потому что
там же достаётся `chat_id` из `update["message"]["chat"]["id"]`.

Изменения:

- `send_reply(chat_id, reply, *, incoming_message_id=None)` — новый
  необязательный параметр.
- Внутри: если `incoming_message_id` задан — удалить его (best-effort, тот же
  паттерн, что уже есть для `_delete_previous_redirect`: глотать
  `TelegramPublishError`, не ронять обработку апдейта).
- Трекинг «последнее сообщение бота в чате» (переименовать
  `_last_redirect_message` → `_last_bot_message`) применяется к каждому
  вызову `send_reply`, а не только к `is_redirect`.
- `bot_polling.py` и `api/telegram.py`: передать
  `message.get("message_id")` в `send_reply` как `incoming_message_id`.

### Что не меняется

- Тексты и клавиатуры команд — как есть.
- Поведение при ошибке удаления — best-effort, как в текущем мини-фиксе.
- `parse_mode=HTML`, экранирование, retry через `telegram_publisher` — без
  изменений.

## 2. Онбординг + юридический дисклеймер

Дисклеймер добавляется только в `WELCOME` (`telegram_bot.py`, показывается на
`/start` без payload — первый контакт и обычное открытие главного меню).
Профиль в Mini App не трогаем.

Текст (добавляется отдельным абзацем в конец `WELCOME`):

> ℹ️ AI Seller — информационный ИИ-каталог, не интернет-магазин. Бот и
> приложение помогают подобрать технику и оформить заявку; сама сделка —
> оплата и передача товара — проходит очно, наличными, при получении.
> Онлайн-оплаты и дистанционной продажи здесь нет.

**Оговорка (проговорить пользователю в спеке явно, не только в чате).** Этот
текст снимает риск квалификации сервиса как «дистанционной торговли» —
правил, которые применяются к продавцам без личного контакта с покупателем до
оплаты (публичная оферта, право отказа в течение 7 дней и т.п.). У магазина
оплата и передача товара очные, и текст это подчёркивает.

Он **не снимает** риск незаконного предпринимательства (ст. 171 УК РФ /
ст. 14.1 КоАП), если систематическая торговля ведётся без регистрации точки
на Горбушке. Это вопрос оформления бизнеса (минимум ИП — самозанятость для
перепродажи техники не подходит), а не формулировок в боте, и одним текстом в
Telegram не закрывается. Решение — за владельцем, при необходимости с юристом
или бухгалтером.

## 3. Вне патча

- **`startapp=` вместо `start=` в кнопках канала** (полный аналог DTM: клик
  открывает Mini App напрямую, без захода в чат бота и без сообщения `/start`
  в принципе) — уходит отдельной задачей в `PATCH_2.0.md`, фаза 1
  («Атрибуция и посадка»), где уже отмечен смежный долг: фронт не читает
  `initDataUnsafe.start_param`. Совмещать оба изменения разумнее, чем делать
  наспех сейчас.
- Дублирование дисклеймера в профиле Mini App — не делаем (см. ответ
  владельца выше).

  только для редиректа;

  `deleteMessage` для `N`;

  всё равно обрабатывается, ошибка глотается;
- `bot_polling.py`/`api/telegram.py`: проверить, что `message_id` реально
  прокидывается в `send_reply` (можно через существующие тесты вебхука, если
  они мокают `send_reply`).

подстроки, как для других констант текста в этом файле).
