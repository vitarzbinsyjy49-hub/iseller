## 1. Что у Лавки

Вкладка каталога — не список категорий, а свёрстанная витрина:

```
Скидки        Зоотовары     Аптека      Новинки      ← лента ярлыков

Придумано Яндекс Лавкой                              ← рубрика
[«Из Лавки»] [Летние новинки] [«Лавка 100»]

Готовая еда                                          ← рубрика
[Вся готовая еда] [«Есть горячее»] [Кофейня]

Овощной прилавок                                     ← рубрика
[Самый сезон] [Овощи, грибы, зелень] [Фрукты и ягоды]
```

Три приёма работают вместе:

1. **Рубрики с заголовками** — категории сгруппированы по смыслу, а не свалены
   одной сеткой.
2. **Плитки разного размера** — в «большой лавке» «Скидки» занимают 2/3 ширины,
   «Аптека» 1/3, остальные — треть каждая. Размер = важность.
3. **Фото реальных предметов на цветной подложке**, а не иконки. Пастельная
   заливка своя у каждой рубрики (голубая, жёлтая, зелёная) — она и склеивает
   группу визуально.

## 2. Что у нас сейчас

Плитки главной живут в таблице `home_categories` и редактируются в админке
(раздел «Главная»): `title`, `emoji`, `icon_url`, `background_gradient`,
`action_type`, `action_value`, `position`, `is_active`. `GET /api/home` уже
умеет:

- скрывать плитку без товаров (`has_products()`);
- добавлять новую категорию автоматически (`_auto_tile`);
- разводить плитки на две оси — категории и бренды.

То есть **половина механики уже есть**. Нет только двух вещей: группировки в
рубрики и разных размеров.

## 3. Главный риск

> **Списка категорий в коде нет и заводить его нельзя.**

Соблазн этого ТЗ — прописать рубрики массивом в `Catalog.tsx`
(`{ "Техника Apple": ["смартфоны", "ноутбуки"] }`). Так делать нельзя: ровно
такой хардкод уже разъезжался с базой и приводил к плиткам, ведущим в пустой
каталог. Рубрика — это **данные**, редактируемые в админке, как и порядок плиток.

Если решение «сделаем массив в коде, потом перенесём» будет принято — этот
пункт лучше не делать вовсе.

## 4. Что делаем

### 4.1 Схема: две новые колонки в `home_categories`

| колонка | тип | смысл |
|---|---|---|
| `group_title` | `VARCHAR(80) NULL` | заголовок рубрики. `NULL`/пусто — плитка идёт в общую сетку без заголовка |
| `size` | `VARCHAR(8) NOT NULL DEFAULT 'sm'` | `sm` (треть) / `lg` (две трети) |

Порядок рубрик — по минимальной `position` входящих в неё плиток. Отдельной
таблицы рубрик не заводим: она потребовала бы своего CRUD, а рубрика без плиток
не существует так же, как категория без товаров.

**Обязательные шаги при добавлении колонок (иначе деплой ляжет):**

1. Мини-миграция в `backend/app/main.py`, рядом с существующими:
   ```sql
   ALTER TABLE home_categories ADD COLUMN IF NOT EXISTS group_title VARCHAR(80)
   ALTER TABLE home_categories ADD COLUMN IF NOT EXISTS size VARCHAR(8) DEFAULT 'sm'
   ```
   `Base.metadata.create_all` создаёт только новые таблицы; колонки в
   существующих — руками.
2. Проверить `REQUIRED_SCHEMA` в `backend/app/scripts/bot_polling.py`. Сейчас
   `home_categories` там не перечислена — значит бот эти колонки не читает и
   дописывать не нужно. **Но проверить обязательно**: колонка, которую бот
   тянет через ORM и которой ещё нет в базе, роняет его на деплое с
   `UndefinedColumn`. Тест
   `test_required_schema_covers_every_mini_migration_column` держит списки
   сомкнутыми — если он покраснеет, добавить колонки в `REQUIRED_SCHEMA`.

### 4.2 API

`GET /api/home` — добавить `group_title` и `size` в `to_dict()` плитки. Формат
ответа не ломаем: старый фронт просто игнорирует новые поля.

Группировку **считает фронт**, а не backend: это чисто представленческое
решение, и держать его в чистой функции с тестом дешевле, чем в SQL.

### 4.3 Админка

В редакторе плитки — два новых поля: «Рубрика» (текст с автодополнением по уже
существующим значениям) и «Размер» (переключатель `sm`/`lg`).

Автодополнение обязательно: без него появятся «Техника Apple» и «Техника  Apple»
с двумя пробелами, и это будут две разные рубрики. Значение перед сохранением
нормализуем (`strip`, схлопывание пробелов).

### 4.4 Фронт

`/catalog` — сетка плиток вместо/над текущим рядом категорий:

- плитки с одинаковым `group_title` идут подряд под общим заголовком;
- плитки без рубрики — общей сеткой в конце, без заголовка;
- `size: lg` занимает 2 колонки из 3, `sm` — одну;
- подложка плитки — `background_gradient` из админки (поле уже есть);
- изображение — `icon_url`, если задан; иначе `emoji`; иначе `FALLBACK_ICON`.
  **Каскад обязателен**: плитка без картинки не должна превращаться в пустой
  цветной прямоугольник.

Правила видимости остаются прежними и **не дублируются на фронте**: что
показывать, уже решил `/home` (пустые скрыты, новые добавлены). Фронт только
раскладывает.

## 5. Логика — в `lib/catalogTiles.ts`

```ts
export type TileGroup = { title: string | null; tiles: HomeCat[] };

/** Разложить плитки по рубрикам, сохранив порядок из position. */
export function groupTiles(tiles: HomeCat[]): TileGroup[]
```

Тесты:
- пусто → `[]`;
- плитки без `group_title` → одна группа с `title: null`;
- порядок рубрик — по минимальной `position` внутри каждой;
- порядок плиток внутри рубрики — по `position`;
- `group_title` с разным регистром и лишними пробелами (`«Apple »` и `«apple»`)
  считается **одной** рубрикой, заголовок берётся у первой по `position`;
- одна плитка в рубрике — рубрика всё равно рисуется (это осознанное решение
  контент-менеджера, а не ошибка).

## 6. Что делать НЕ надо

- **Не рисовать фото-подложки без фотографий.** Приём Лавки держится на
  предметной съёмке. Пока в `icon_url` лежат эмодзи и стоковые иконки, разные
  размеры плиток только подчеркнут пустоту крупной. Если снимков не будет —
  делать §4.1–4.3 (рубрики) и **не делать** `size: lg`.
- **Не заводить третью ось навигации.** Оси две (категории и бренды), и промо
  живут на оси категорий — это записано в `api/home.py` явно.
- **Не переносить рубрики на главную** в этом ТЗ. Главная и так плотная;
  рубрики — ответ на вопрос «покажи всё», а он задаётся в каталоге.

## 7. Порядок работ

1. Колонки + мини-миграция + поля в `to_dict()` (backend, полдня).
2. Поля в админке с автодополнением (полдня).
3. **Контент: разложить существующие плитки по рубрикам руками.** Это не код и
   делается владельцем каталога. Пока этот шаг не сделан, фронт показывает одну
   безымянную группу — то есть ровно то, что сейчас, и релизить можно без
   ожидания контента.
4. `groupTiles` + тест (час).
5. Вёрстка сетки в `Catalog.tsx`.
6. Размеры плиток — **только после того, как появятся фотографии**.

- [ ] Автодополнение в админке не даёт создать рубрику-дубль с пробелом.
