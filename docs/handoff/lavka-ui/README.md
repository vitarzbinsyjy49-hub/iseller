## 0. Зачем это

Лавка — эталон плотного мобильного магазина: за 19 секунд человек проходит
главную, поиск, выдачу, каталог, корзину и профиль, и ни на одном экране не
теряет ни статус заказа, ни сумму, ни путь назад. Мы берём **механику**, а не
внешность: жёлтые CTA, минутный ЕТА и импульсные покупки на 50 ₽ к магазину
техники не относятся (см. §3).

Каждый пункт — отдельный, самодостаточный документ. Их можно брать в работу по
одному и в любом порядке; общих зависимостей между ними нет, кроме отмеченных
явно.

## 2. Общие правила для всех пунктов

**Инварианты проекта, которые нельзя нарушить ни одним из ТЗ:**

1. **Списка категорий в коде нет.** Любая рубрикация приходит из данных
   (`services/catalog_nav.py`, `home_categories`). Хардкод разъезжается с базой
   и ведёт в пустой каталог — это уже случалось.
2. **Не обещать того, чего backend не отдаёт.** Ни бесплатной доставки, ни
   сроков, ни скидок «от суммы». Если данных нет — блок не рисуется вовсе.
   Так уже сделано в `CartBar.tsx`, и это решение остаётся в силе.
3. **Одна фиксированная панель на экран.** Правило живёт в
   `cartMath.shouldShowCartBar()`; любая новая нижняя панель обязана проходить
   через него, иначе две полосы встают друг на друга.
4. **Safe-area учитывается ровно один раз** — через `--bottom-nav-height`
   (`index.css`). Складывать `env()` и Telegram-инсет нельзя: на iPhone это
   даёт двойной отступ.
5. **Клавиатура прячет нижние панели** — класс `js-bottom-nav` + `html.kb-open`.
6. **Чистая логика — в `lib/*.ts` с тестом рядом.** Всё, что можно посчитать
   без React (какие чипы показать, что писать в доке, как сгруппировать
   выдачу), выносится в функцию и покрывается vitest — как `navTiles`,
   `cartMath`, `catalogFilters`.
7. **Тач-таргет ≥ 44×44** даже там, где элемент визуально ниже (`min-h-11`).
8. **Каждое новое действие логируется** через `track()` из `lib/analytics.ts`.
   Имя события — snake_case, с полем `source`, как у существующих.

**Проверка перед сдачей любого пункта:**

```bash
cd frontend && npx tsc --noEmit && npx vitest run && npm run build
```

Плюс визуальная проверка **на живом устройстве в Telegram**, а не в dev-браузере:
`html.kb-open`, safe-area и инерционная прокрутка в WebView ведут себя иначе.

## 3. Что из Лавки мы сознательно НЕ берём

Эти отказы — часть ТЗ. Если они всплывут в ревью как «а почему не сделали» —
ответ здесь.

| приём Лавки | почему не нам |
|---|---|
| Минутный ЕТА («5–15 мин», «Будем к 18:29») | У нас лид, а не доставка. Любой таймер здесь — обещание, которого никто не давал. |
| «+» как основной способ покупки | У Лавки импульс на 50 ₽, у нас ноутбук за 150 000 ₽ с выбором конфигурации. Степпер на карточке — потолок, дальше в сторону one-tap идти вредно. |
| 4 рекламных блока на первом экране | В Mini App это читается как спам; у нас баннеры уже ограничены лентой из админки. |
| Жёлтая CTA-плашка | Цвет бренда Лавки. Наш акцент — Telegram-blue, менять не за чем. |
| Маскот в пустых состояниях | Отдельная иллюстрационная система, которой у нас нет и заводить её ради одного экрана дорого. |
| Переключатель «магазин у дома / большой склад» как смена ассортимента | У нас один склад. Ось «Категории / Бренды» — наш аналог, и он уже есть (см. ТЗ 03). |
