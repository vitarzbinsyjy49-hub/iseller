## 1. Что у Лавки

Между баннерами и товарными секциями — узкая полоса:

```
┌────────────────────────────────────────────────┐
│ Будем к 18:29 ›                    [🥛][🥒]    │
│ Собираем заказ                                 │
└────────────────────────────────────────────────┘
```

Слева — главное (когда), под ним — что происходит прямо сейчас, справа —
миниатюры товаров из заказа. Полоса стоит **в потоке главной**, а не поверх неё,
и исчезает, когда активного заказа нет.

Приём отвечает на единственный вопрос вернувшегося покупателя: «что с моим
заказом?» — не заставляя его идти в раздел заказов.

## 2. Что у нас сейчас

Заявки живут на `/requests` (`Requests.tsx`, `GET /api/leads/my`). На главной о
них нет ни слова. Человек, оформивший заявку вчера, открывает приложение и
видит ровно то же, что видел до неё: баннеры и каталог.

При этом статус меняется реально: `new → in_progress → reserved → completed`,
менеджер оставляет `manager_comment`, и уведомление уходит в Telegram
(`services/notifications.py`). То есть данные для полосы есть и живые.

## 3. Что делаем

Полоса на главной, **выше ленты баннеров** (в `Home.tsx` — сразу после
`QuickScenarios`, до `HeroBanner`-ленты), при наличии активной заявки.

```
┌────────────────────────────────────────────────┐
│ Заявка №128 · В работе  ›            [◻][◻]+2 │
│ Менеджер подтверждает наличие и цену           │
└────────────────────────────────────────────────┘
```

- **Строка 1:** номер заявки (`public_number`) + статус текстом
  (`STATUS_LABEL`) + шеврон. Статус — тем же словарём и теми же цветами, что на
  `/requests`: два разных названия одного статуса на соседних экранах хуже, чем
  одно скучное.
- **Строка 2:** пояснение статуса одной фразой (см. §5).
- **Справа:** до 3 миниатюр товаров из `items[].image`, дальше «+N».
  У заявки без позиций (сценарная — Trade-In, «Продать», оптовый запрос)
  миниатюр нет, справа пусто.
- Вся полоса — ссылка на `/requests` (без якоря на конкретную заявку: экран
  фильтруется по статусу, и заявка будет первой в списке).

### 3.1 Какая заявка считается активной

Активные статусы: `new`, `in_progress`, `reserved`.
`completed` и `cancelled` — не активные, полоса для них не рисуется.

Если активных несколько — показываем **одну, самую свежую** по `created_at`, а в
конце первой строки добавляем «· ещё N». Стопка полос на главной — это уже
список заявок, а он у нас есть и называется `/requests`.

Если активных нет — **полосы нет**, вертикальный ритм смыкается.

## 4. Данные

`GET /api/leads/my` — существующий эндпоинт, менять backend не нужно. Отдаёт всё
необходимое:

| поле | зачем |
|---|---|
| `public_number` | «Заявка №128» |
| `status` | подпись и цвет |
| `created_at` | выбор самой свежей |
| `items[].image` | миниатюры (`image_snapshot` в `lead_items`) |
| `items_count` | «+N» |
| `manager_comment` | **не показываем** — см. §5 |

Запрос добавить в общий `useEffect` главной. Ошибка запроса = полосы нет; ни
скелетона, ни сообщения об ошибке — статус заявки не настолько срочен, чтобы
из-за него показывать красное на первом экране.

⚠️ `/leads/my` требует авторизации. На главной пользователь уже
авторизован (весь `/home` под `get_current_user`), отдельной обработки нет.

## 5. Тексты статусов

Одна фраза на статус, без сроков и без обещаний:

| статус | вторая строка |
|---|---|
| `new` | Менеджер скоро свяжется с вами |
| `in_progress` | Менеджер подтверждает наличие и цену |
| `reserved` | Товар забронирован за вами |

**`manager_comment` в полосу не выводим.** Это свободный текст из админки: он
бывает длиной в абзац, бывает внутренней пометкой и не рассчитан на витрину.
Его место — карточка заявки на `/requests`, где есть ширина и контекст.

**Сроков не пишем ни в каком виде.** Ни «ответим за 15 минут», ни «сегодня»:
такого обязательства backend не хранит, и полоса не должна его выдумывать —
то же правило, по которому `CartBar` не обещает бесплатную доставку.

## 6. Логика — в `lib/activeLead.ts`

```ts
export type LeadStripData = {
  id: number;
  number: string;
  statusLabel: string;
  statusStyle: string;
  hint: string;
  thumbs: string[];   // максимум 3
  more: number;       // сколько ещё позиций сверх показанных
  otherActive: number; // сколько ещё активных заявок
} | null;

export function activeLeadStrip(leads: Lead[]): LeadStripData
```

`STATUS_LABEL` и `STATUS_STYLE` **переезжают из `Requests.tsx` сюда** и
импортируются обоими экранами. Копия словаря в двух файлах разъедется — это тот
же класс ошибки, что захардкоженные категории.

Тесты (`activeLead.test.ts`):
- пустой список → `null`;
- только `completed`/`cancelled` → `null`;
- одна активная → корректные подпись, миниатюры, `more`;
- несколько активных → выбрана самая свежая по `created_at`, `otherActive = n-1`;
- заявка без `items` (сценарная) → `thumbs: []`, `more: 0`, полоса всё равно есть;
- 5 позиций → `thumbs.length === 3`, `more === 2`;
- позиция без `image` пропускается, но считается в `more` (миниатюра-заглушка в
  полосе не нужна — она читается как «товар без фото», а это не тот сигнал).

## 7. Вёрстка

- Контейнер `rounded-xl2 bg-surface p-3.5 shadow-card` — карточка, как
  AI-консьерж-CTA ниже по странице. Здесь тень уместна: полоса сообщает о
  событии, происходящем прямо сейчас, и должна стоять чуть выше фона.
- Миниатюры 32×32, `rounded-lg`, с отрицательным перекрытием -8px (стопка), как
  у Лавки.
- Первая строка `text-[15px] font-bold`, вторая `text-[12px] text-muted`.
- `min-h-11` на кликабельной области.
- На desktop полоса тоже показывается (в колонке контента, не в сайдбаре) —
  вопрос «что с заявкой» одинаков на обоих устройствах.

## 9. Крайние случаи

- **Заявку отменили на `/requests`** и вернулись на главную — данные
  перезапрашиваются, полоса исчезает. Проверить, что переход не «прыгает».
- **Очень длинный `public_number`** — первая строка `truncate`, миниатюры
  никогда не сжимаются.
- **10+ активных заявок** (оптовик) — «· ещё 9», полоса одна.
- **Тёмная тема** — миниатюры на тёмном фоне нуждаются в рамке `ring-1
  ring-border`, иначе белые фото товаров сливаются в пятно.

## 10. Готово, когда

- [ ] Полоса появляется при активной заявке и исчезает после её завершения.
- [ ] Статусы называются и красятся одинаково на главной и на `/requests`
      (словарь один, импортируется из `lib/activeLead.ts`).
- [ ] `manager_comment` на главную не попадает.
- [ ] Ни одного срока в тексте полосы.
- [ ] Сценарная заявка без позиций рисуется корректно.
- [ ] `activeLead.test.ts` зелёный.
- [ ] Проверено на проде с настоящей заявкой, а не на фикстуре.
