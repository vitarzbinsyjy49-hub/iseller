# ТЗ 03 — Счётчики в сегменте «Категории / Бренды»

**Оценка:** S (полдня) · **Файлы:** `frontend/src/components/SegmentedToggle.tsx`,
`frontend/src/pages/Home.tsx` · **Референс:** `frames/01-home.jpg`, `frames/12-catalog.jpg`

---

## 1. Что у Лавки

Сегмент-переключатель наверху главной — двухстрочный:

```
┌─────────────────────┬─────────────────────┐
│   лавка у дома      │   большая лавка     │
│   5 000 товаров     │   10 000 товаров    │
└─────────────────────┴─────────────────────┘
```

Вторая строка — не украшение, а ответ на вопрос «зачем мне туда переключаться».
Без неё «большая лавка» — просто второе слово; со счётчиком — обещание вдвое
большего выбора. Человек нажимает осознанно, а не наугад.

## 2. Что у нас сейчас

`SegmentedToggle` — один компонент на два места: ось «Категории / Бренды» на
главной (`Home.tsx:497`) и (исторически) «Каталог / AI» в строке поиска. Опция —
`{ value, label }`, одна строка, высота `h-11` фиксирована намеренно (иначе
вёрстка прыгает при переключении).

Проблема ровно та же, что у Лавки без счётчиков: тумблер «Категории / Бренды» не
объясняет, что найдётся на второй вкладке. У кого в каталоге три бренда, тот
переключится, увидит три плитки и больше не вернётся.

## 3. Что делаем

Добавить в `SegmentedOption` необязательное поле `hint`:

```ts
export type SegmentedOption<T extends string> = {
  value: T;
  label: string;
  /** Вторая строка: «12 категорий», «5 брендов». Необязательна —
   *  без неё тумблер рисуется как раньше, в одну строку. */
  hint?: string;
};
```

Правила рендера:

1. **Если `hint` нет ни у одной опции — компонент не меняется вовсе.** Высота
   `h-11`, одна строка. Существующие использования не трогаем и не
   перепроверяем.
2. Если `hint` есть **хотя бы у одной** опции — обе позиции переходят в
   двухстрочный режим и получают общую увеличенную высоту (`h-14`). Разная
   высота у двух половин одного тумблера недопустима.
3. Опция без `hint` в двухстрочном режиме держит подпись по центру по
   вертикали — не рисуем пустую вторую строку.
4. **Высота остаётся фиксированной внутри режима.** Причина та же, что записана
   в комментарии компонента: тумблер стоит в потоке над рядом чипов, и «прыжок»
   при переключении заметен сразу.

На главной:

```tsx
options={[
  { value: "category", label: "Категории", hint: countHint(categoriesCount, "категория") },
  { value: "brand",    label: "Бренды",    hint: countHint(brandsCount, "бренд") },
]}
```

## 4. Данные

Ничего нового. `GET /api/home` уже отдаёт готовые массивы `categories` и
`brands`, **уже отфильтрованные** по `has_products()` — то есть длина массива и
есть честный счётчик видимых разделов.

```ts
const categoriesCount = navTiles("category", home, categories).length;
const brandsCount = (home?.brands ?? []).length;
```

**Считаем разделы, а не товары.** «12 категорий» — правда, которую можно
проверить тапом. «5 000 товаров» мы бы посчитать смогли (`category_counts`
суммой), но это число нигде больше в интерфейсе не встречается, а всякое число,
которое не с чем сверить, живёт как реклама.

Тумблер по-прежнему рисуется только при `hasBrandAxis` — ось без содержимого не
показывается вовсе, и это правило важнее счётчиков.

## 5. Плюрализация

Функция `countHint` — в `lib/format.ts` рядом с `pluralItems`, либо
переиспользовать общий помощник, если он появится:

| n | категории | бренды |
|---|---|---|
| 1 | 1 категория | 1 бренд |
| 2–4 | 3 категории | 3 бренда |
| 5+, 11–19 | 12 категорий | 12 брендов |

Тест — в `format.test.ts`, кейсы 1, 2, 5, 11, 12, 21, 111.

## 6. Крайние случаи

- **Одна категория и один бренд** — тумблер всё ещё показывается (ось не
  пустая), счётчики «1 категория» / «1 бренд». Выглядит бедно, но честно; это
  сигнал контент-менеджеру, а не повод прятать цифру.
- **Узкий экран (320px)** — двухстрочный тумблер шире однострочного по высоте, но
  не по ширине; подписи `text-[11px]`, `truncate` на всякий случай.
- **Кэш категорий** (`categoryCache.ts`) может дать число, отличное от свежего
  `/home` на доли секунды — допустимо, счётчик обновится молча, без анимации.
- **Клавиатурная навигация** стрелками (`onKeyDown`) остаётся без изменений.
