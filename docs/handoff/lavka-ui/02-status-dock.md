# ТЗ 02 — Однострочный статус-док с прогрессом лояльности

**Оценка:** M (1–2 дня) · **Файлы:** `frontend/src/components/CartBar.tsx`,
`frontend/src/lib/cartMath.ts`, `frontend/src/lib/loyalty.ts`, `index.css` ·
**Референс:** `frames/01-home.jpg` (зелёный док), `frames/12-catalog.jpg` (оранжевый)

---

## 1. Что у Лавки

Над нижней навигацией — **одна строка** высотой ~44px, видимая на всех экранах:

```
[🛒 37 ₽ ▓▓▓▓▓▓▓░░░░░░░░░░░░░░░ (0 Р)]
          Доставка 5–15 мин ›
```

Три вещи в одной полосе: текущая сумма слева, **полоса прогресса до цели**
фоном, цель справа. Под ней — одна серая строка контекста, кликабельная.

Ключевое: при переключении на «большую лавку» весь док перекрашивается из
зелёного в оранжевый и показывает другую сумму и другой срок. **Цвет дока =
режим магазина.** Это дешёвый способ держать статус на глазах, не занимая
второй строки контента.

## 2. Что у нас сейчас

`CartBar.tsx` — карточка на две строки: иконка с бейджем количества, «3 товара ·
189 990 ₽», подпись «Сумма предварительная», кнопка «Корзина →». Показывается
только когда в корзине что-то есть, и прячется по `shouldShowCartBar()` на
`/cart`, `/product/*`, `/ai`, `/sell`.

Проблемы:
- **высота.** Две строки + кнопка = ~68px поверх 5-табной навигации; на iPhone SE
  под это уходит четверть экрана;
- **пустой статус.** Пока корзина пуста (а это большинство сессий), полоса не
  несёт ничего;
- **«Сумма предварительная»** — единственная подпись, и она честная, но
  бесполезная: человек и так знает.

## 3. Что делаем

Переписать `CartBar` в однострочный док. Заменяем не смысл, а плотность.

### 3.1 Состояние «в корзине есть товар» (главное)

```
┌──────────────────────────────────────────────┐
│ 🛒3   189 990 ₽  ▓▓▓▓▓▓▓░░░░░░░░  Серебро →  │
└──────────────────────────────────────────────┘
        Сумма предварительная · Корзина ›
```

- слева — иконка с бейджем количества (как сейчас, но 32px);
- сумма `estimated_total`, `font-bold`;
- **фоном полосы — прогресс лояльности** (`ratio` из `/api/loyalty/me`), а не
  выдуманный порог бесплатной доставки. Это тот же прогресс, что уже рисуется
  на `/loyalty` через `progressPercent()` из `lib/loyalty.ts`;
- справа — название следующего уровня (`next_level.title`) и шеврон;
- весь док — одна кнопка, ведёт в `/cart` (как сейчас).

### 3.2 Состояние «корзина пуста»

Док **не рисуется**. Мы не Лавка: у нас нет доставки, о статусе которой нужно
сообщать постоянно, и полоса «0 ₽ до серебра» на пустой корзине — это реклама
программы лояльности, а не статус. Правило `shouldShowCartBar()` остаётся.

### 3.3 Когда лояльности нет

`next_level === null` (человек на максимальном уровне) или запрос
`/loyalty/me` не удался — **полоса прогресса и правая часть не рисуются
вовсе**, док остаётся однострочным: `[🛒3] 189 990 ₽ ··· Корзина →`.

Это прямое применение правила «не обещать того, чего backend не отдаёт»: пустой
серый жёлоб без цели выглядит как сломанный элемент.

## 4. Данные

| что | откуда | кэш |
|---|---|---|
| сумма, количество | `useCart()` — уже есть | — |
| `ratio`, `next_level`, `to_next` | `GET /api/loyalty/me` → `fetchLoyalty()` из `lib/loyalty.ts` | **запрашивать один раз на сессию**, не на каждый рендер дока |

`GET /loyalty/me` отдаёт ещё `history` (до 30 записей) — для дока это лишний
вес. Если профилировка покажет, что ответ тяжёлый, добавить `?history_limit=1`;
менять backend не нужно, параметр уже есть.

**Прогресс считается по `lifetime_spent`, а не по текущей корзине.** Заявка ещё
не оформлена, баллы за неё не начислены — рисовать её вклад в полосе значит
обещать начисление до подтверждения менеджером. Полоса показывает, где человек
находится сейчас; подпись справа — куда он идёт.

## 5. Вёрстка и геометрия

- Высота дока — **48px** (одна строка + собственные паддинги), плюс
  строка-подпись 16px = 64px против нынешних ~68px+. Выигрыш небольшой в
  пикселях, но большой в читаемости: одна доминанта вместо трёх.
- Полоса прогресса — `background: linear-gradient(...)` на самом контейнере
  кнопки (как у Лавки), а не отдельный `<div>` под текстом. Заливка
  `bg-accent/12`, поверх — обычный текст. Контраст текста проверить на
  заполненной и пустой части: **≥4.5:1 в обоих случаях**.
- `--bottom-nav-height` из `index.css` не трогать. Safe-area учитывается ровно
  один раз — там же, где сейчас. Если высота дока меняется, править переменную,
  а не добавлять `env()` во второй раз (на iPhone это давало двойной отступ).
- `js-bottom-nav` остаётся: при `html.kb-open` док прячется вместе с навигацией.
- `z-30` остаётся: ниже навигации (`z-40`), перекрыть её док не может.

## 6. Логика — в `lib/cartMath.ts` (или новый `dockState.ts`)

```ts
export type DockState =
  | { kind: "hidden" }
  | { kind: "cart"; total: number; count: number;
      progress: { percent: number; nextTitle: string } | null };

export function dockState(input: {
  pathname: string;
  itemsCount: number;
  estimatedTotal: number;
  loyalty: { ratio: number; next_level: { title: string } | null } | null;
}): DockState
```

Тесты (`cartMath.test.ts` дополнить или отдельный файл):
- `/cart`, `/product/1`, `/ai`, `/sell` → `hidden` (существующие кейсы
  `shouldShowCartBar` **не переписывать, а переиспользовать** — правило одно);
- пустая корзина → `hidden`;
- `loyalty === null` → `progress === null`, а не `percent: 0`;
- `next_level === null` (максимальный уровень) → `progress === null`;
- `ratio` 0 → `percent` 0 (не «немного для красоты»); `ratio` 0.01 → минимальная
  видимая ширина, как в существующем `progressPercent()`.

## 7. Аналитика

Существующее `track("cart_open", { source: "cart_bar", items_count })` сохранить
без переименования — иначе разорвётся ряд в аналитике. Добавить поле:

```ts
track("cart_open", { source: "cart_bar", items_count, has_progress: boolean });
```

## 8. Крайние случаи

- **Длинное название уровня** («Платиновый») + шестизначная сумма на 360px —
  правая часть `truncate`, сумма не сжимается никогда.
- **Сумма меняется** (добавили товар с другого экрана) — число обновляется без
  анимации ширины полосы: прогресс лояльности от корзины не зависит и дёргаться
  не должен.
- **Тёмная тема Telegram** — проверить заливку прогресса: `accent/12` на тёмном
  фоне почти не видна, нужен свой токен.
- **Один товар** — «1 товар» через `pluralItems()`, но в новом доке
  количество ушло в бейдж; текст плюрализации в доке больше не участвует.
  Убедиться, что `pluralItems` не осиротела (её использует ещё `/cart`).

## 9. Готово, когда

- [ ] Док однострочный, высота ≤64px вместе с подписью.
- [ ] На пустой корзине дока нет; на `/cart`, `/product/*`, `/ai`, `/sell` — нет.
- [ ] При недоступном `/loyalty/me` док работает и выглядит цельно.
- [ ] `/loyalty/me` вызывается один раз на сессию, а не на каждый рендер.
- [ ] Контраст текста на заполненной и пустой части полосы ≥4.5:1.
- [ ] Тесты состояния дока зелёные, старые кейсы `shouldShowCartBar` живы.
- [ ] Проверено в Telegram на iPhone с открытой клавиатурой (док прячется) и
      на устройстве с включённым «уменьшением движения».
