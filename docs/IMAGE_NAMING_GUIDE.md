# Именование фото товаров (ZIP-загрузка, v4)

Фото загружаются пачкой: **Админка → Медиа → ZIP с фото товаров**
(API: `POST /api/admin/uploads/products/images-zip`).

## Правило именования

Имя файла (до расширения) = **SKU товара**. Суффикс задаёт порядок в галерее:

| Файл | Что это |
|------|---------|
| `IPH15PRO128BLACK.jpg`       | главное фото |
| `IPH15PRO128BLACK_main.jpg`  | главное фото (альтернатива) |
| `IPH15PRO128BLACK-1.jpg`     | второе фото галереи |
| `IPH15PRO128BLACK-2.jpg`     | третье фото галереи |

- Регистр не важен: `iph15pro128black.jpg` тоже сматчится.
- Подпапки внутри ZIP допустимы — учитывается только имя файла.
- Форматы: `jpg / jpeg / png / webp / gif`, до 8 МБ на файл, ZIP до 200 МБ.
- Повторная загрузка ZIP с тем же SKU **заменяет** галерею товара целиком.

## Отчёт после загрузки

- **matched products** — товары, получившие фото (первое фото стало главным);
- **unmatched images** — файлы, для которых SKU не найден (проверьте артикул);
- **products without images** — товары каталога всё ещё без фото;
- **errors** — не-картинки, файлы больше 8 МБ и т.п.

## Где взять SKU

- Каталог сидится с автогенерированными SKU (`IPHONE15PRO128GB` из названия).
- В админке SKU виден и редактируется в карточке товара (Товары → Изменить).
- При импорте прайса SKU берётся из колонки `sku` вашего файла.

## Одиночные картинки

- Фото конкретного товара: Товары → Изменить → Фотографии (грузится сразу).
- Картинка для баннера/категории: Медиа → «Загрузить одну картинку» → копируйте URL
  (или прямо в форме баннера: Главная → Баннеры → Изменить → Картинка).


## v5.2: batch-импорт
В пакетном импорте фото матчатся не только с существующими SKU, но и с теми, которые создаются той же job (можно грузить прайс и фото одним пакетом). Формат имён не изменился.

## v5.4.0: лимит 10 фото и порядок
- На товар/эффективную группу — максимум **10 фото** (`MAX_PRODUCT_IMAGES`), enforced на
  бэкенде во всех путях. 11-е фото не принимается (400).
- ZIP/импорт с >10 фото одного SKU: первые 10 по текущей сортировке применяются, остальные
  попадают в отчёт `excess_images` (в UI — «Не применено (лимит 10 фото)»). Ничего не теряется молча.
- Порядок галереи стабилен, главная = первое фото. В админке (Товары → Изменить → Фотографии):
  мультизагрузка (несколько файлов сразу и drag-and-drop), счётчик «Фотографии · N/10»,
  кнопки ← → для порядка, «Главная» ставит фото первым. Порядок сохраняется и переживает reload.
- Аудит покрытия: раздел «Медиа» → «Покрытие каталога фото» + скрипт
  `scripts/photo_coverage_audit.py` (см. `docs/SCENARIO_LEADS_AND_GALLERY.md`).
