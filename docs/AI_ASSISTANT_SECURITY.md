# AI-консультант: безопасность (v5)

## Границы доверия
```
[Пользователь: НЕДОВЕРЕННЫЙ] → JWT → [VPS backend: доверенный]
    → X-API-Key + приватная сеть → [Gateway: доверенный, но изолированный]
        → localhost → [Ollama/LLM: ВЫВОД НЕДОВЕРЕННЫЙ]
```
Правило: всё, что исходит от пользователя И от LLM — данные, не команды.

## Реализованные меры
| Угроза | Защита | Где |
|---|---|---|
| Прямой доступ к Ollama из интернета | Ollama слушает 127.0.0.1; Gateway — только приватная сеть (Tailscale); публичного порта нет | инфраструктура |
| Неавторизованные вызовы Gateway | X-API-Key, `hmac.compare_digest` (constant-time) | gateway `_check_api_key` |
| DoS Mac mini | payload ≤64KB, история ≤10, кандидаты ≤12, rate limit 30/мин, semaphore(2), timeout 45с | gateway |
| DoS backend-роута | существующий rate limit 10/мин на user_id (fail-open) | `core/rate_limit.py` |
| Выдуманные товары/цены | product_id строго ∩ кандидатов; карточки и цены только из БД (`to_card`) | orchestrator шаг 3 |
| Prompt injection из сообщений | системный промпт: ввод = данные; санитизация control chars; правила не переопределяются | prompt + `_sanitize` |
| Prompt injection из карточек | описания товаров НЕ передаются в LLM; только структурированные поля с обрезкой длины | `candidate_payload` |
| Утечка системного промпта | промпт запрещает раскрытие; наружу уходит только валидированный JSON-ответ; при мусоре — fallback | prompt + parse |
| Сырой JSON/traceback пользователю | parse → repair → fallback; исключения не сериализуются в ответ | orchestrator |
| Утечка IP/модели/стека | тексты ошибок нейтральные; `meta.model=null`; имена исключений только в серверных логах | ai_remote/orchestrator |
| Секреты в git | ключи только в `.env` (в .gitignore); `.env.example` с плейсхолдерами; health не отдаёт секреты | repo |
| PII в логах | gateway логирует метрики (длины/тайминги), не содержимое; backend не пишет initData/телефоны в AI-логи | logging |
| Произвольные tool calls / shell от LLM | инструментов у модели нет вообще: единственный выход — JSON-текст, парсящийся в фикс. схему | архитектура |
| Изменение БД со стороны LLM | Gateway не имеет доступа к БД; backend по ответу LLM только ЧИТАЕТ товары; заявки создаёт лишь пользователь руками | архитектура |

## CORS
Не менялся: DEV_MODE=false требует явный ALLOWED_ORIGINS (иначе backend не стартует).

## Ротация ключа
1. `openssl rand -hex 32` → 2. обновить `ai-gateway/.env`, перезапустить gateway →
3. обновить `AI_GATEWAY_API_KEY` на VPS, пересоздать backend. Просто и без даунтайма
(на время рассинхрона работает fallback).

## Что осталось на сознательном контроле оператора
- Не публиковать порт 8100 наружу (проверка: `curl http://<публичный-ip-мака>:8100` извне должен падать).
- Не коммитить `.env` (уже в .gitignore).
- Обновлять Ollama (`brew upgrade ollama`) — патчи безопасности.
