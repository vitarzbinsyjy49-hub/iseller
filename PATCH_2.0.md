## 1. Порядок фаз и почему он такой

```
атрибуция  →  цены  →  виральность  →  деньги  →  контент-машина
   ↑             ↑
   |             └── предусловие рекламы, а не отдельная цель
   └── предусловие бюджета: залив без меток = цифра, которую нельзя прочитать
```

**Атрибуция первой.** Бюджет на рекламу есть, и первый же залив без меток
источника даёт число посещений, из которого невозможно узнать, какой канал
сработал. Это не «удобнее потом» — это разница между «второй залив умнее
первого» и «второй залив такой же слепой».

**Цены сразу за ней, до рекламы.** Цены BSA поставлены разовым скриптом,
автообновления нет. Реклама, приводящая человека на цену месячной давности,
хуже отсутствия рекламы: он видит расхождение при оформлении и не возвращается
никогда. Поэтому фаза 2 — не «внутренняя работа», а **шлагбаум перед бюджетом**.

**Виральность до денег.** Реферальная механика снижает стоимость привлечения
ровно в тот момент, когда трафик пошёл. Сделанная после — не догоняет уже
приведённых людей.

**Деньги на 7–8 неделе.** Оптимизировать конверсию раньше не на чем: 3 заявки и
11 пользователей не дают сигнала, любое «улучшение» будет обосновано вкусом.

**Контент-машина последней** — она усиливает то, что к тому моменту уже
измеримо.

## 2. Сквозное решение: интерфейс владельца — сменный

Dexo забирает **весь** интерфейс админки. Отсюда правило на весь патч:

> **Ни одна фича этого патча не появляется как экран в `admin/`.**
> Владельческая функция = самодостаточный API + экран поверх него.

Практически это значит:

| правило | почему |
|---|---|
| Вся логика — в `services/`, не в React-компоненте | экран будет переписан, логика — нет |
| Контракт вида `parse → preview → apply` | «показать, что произойдёт» отделено от «сделать» — интерфейс может быть любым |
| Опасное действие всегда за `confirm=true` | защита живёт в API, а не в кнопке, которой в Dexo может не быть |
| Каждый эндпоинт покрыт pytest | тестов интерфейса в проекте нет и не будет — контракт держат тесты API |
| `admin/` только чинится, не развивается | класс Б из `docs/context/admin-audit.md` не лечим, он уезжает в Dexo |

Заготовка уже есть: контракт `parse → match → preview → apply` из
`docs/superpowers/plans/2026-08-07-prelaunch-3-price-tool.md` написан именно так.

## 3. Фазы

Оценка — в сессиях (запрос к агенту с полным прогоном тестов и проверкой).

| фаза | недели | сессий | результат |
|---|---|---|---|
| 1. Атрибуция и посадка | 1–2 | ~5 | известно, откуда пришёл каждый человек |

### Фаза 1 — Атрибуция и посадка (недели 1–2)

**Результат:** про любого пользователя известно, по какой ссылке он пришёл, и
воронка «источник → визит → карточка → корзина → заявка» считается по фактам.

| # | задача | объём |
|---|---|---|
| 1.1 | Метка источника доезжает и записывается | M |
| 1.2 | Посадочные deep link'и на категорию, бренд, подборку | S |
| 1.3 | Реестр кампаний: создать ссылку, получить QR | M |
| 1.4 | Воронка по источникам в отчёте | M |

**1.1 — почему это две задачи, а не одна.** Payload теряется в двух разных
местах и чинится по-разному:

- **вход через бота** (`/start src_xxx`): `parse_start_payload` payload видит, но
  `reply_for_payload` намеренно не ходит в БД — и это правильное свойство, его
  ломать нельзя. Запись источника вешается на обработчик команды, где сессия БД
  уже есть;
- **вход прямо в Mini App** (`startapp=src_xxx`): payload лежит в
  `initDataUnsafe.start_param`, а фронт его **не читает вообще**. Нужно прочитать
  и передать на бэкенд при авторизации.

**Первое касание не перезаписывается.** `source_code` пишется только когда он
пуст. Иначе человек, пришедший из рекламы и позже кликнувший ссылку из канала,
задним числом «придёт из канала» — и рекламный бюджет припишет себе ноль.

**Источник хранится в `users`, а не в `analytics_events`.** Таблица событий
клиентописуемая (`POST /api/events/product` принимает `event_type` из общего
allowlist) — ровно тот случай, который в патче 1.1 запретил считать по ней
social proof. Число, по которому владелец решает, куда потратить следующие
деньги, обязано лежать в серверной таблице фактов.

**1.3 — QR обязателен, потому что аудитория есть вне Telegram.** Ссылку из
Instagram или с офлайн-точки человек руками не набирает.

**Грабли, которые ждут:**

- код кампании приходит из ссылки, то есть его пишет кто угодно — валидация
  строгая (алфавит, длина), иначе получим мусор в колонке и XSS в отчёте;
- payload у Telegram ограничен по длине и алфавиту (`A-Za-z0-9_-`, 64 символа) —
  utm-строку целиком туда не положить, поэтому реестр кампаний и нужен: в ссылке
  короткий код, расшифровка в БД.

### Фаза 2 — Цены и товар без SQL (недели 3–4)

**Результат:** владелец вставляет прайс поставщика с телефона, видит
сопоставление, правит спорное и применяет. Реклама после этого разрешена.

Основа — готовый план `docs/superpowers/plans/2026-08-07-prelaunch-3-price-tool.md`
(30 шагов, 0 отмечено). Он не переписывается, а исполняется, с одной поправкой:
**интерфейс сразу делается под Dexo**, а не как вкладка в `admin/`.

| # | задача | объём |
|---|---|---|
| 2.1 | `services/price_match.py` + тесты на пять известных ловушек | M |
| 2.2 | API `parse → match → preview → apply` | M |
| 2.3 | Журнал применений и откат последней заливки | S |
| 2.4 | Экран поверх API | M |

**Пять ловушек уже стреляли 07.08 и обязаны стать тестами** (из плана фазы 3):
общее слово в бренде (всё Apple схлопывалось в Vision Pro, +300%), квалификатор
модели (Air ↔ Pro, +90%), объём памяти (256 ГБ ↔ 1 ТБ, +60%), поколение чипа
(M5 ↔ M4, −20%), год как цена («2025» разобрано как цена 2025 ₽, −98%). Плюс
шестая — опечатка в наших же данных («шумуоподавлением» у товара 32).

**Пороги «уверенно / проверить / не найдено» — не украшение.** Это
единственная причина, по которой те ошибки заметили до применения.

**2.3 добавлен к плану намеренно.** Ошибочная заливка цен на живой каталог
чинится сейчас только руками через SQL. Откат последней операции стоит одну
таблицу и снимает самый дорогой риск фазы.

### Фаза 3 — Виральность и живая лояльность (недели 5–6)

**Результат:** баллы влияют на цену, приглашение друга приносит выгоду обоим.

| # | задача | зависит от | объём |
|---|---|---|---|
| 3.1 | Списание баллов в корзине | — | M |
| 3.2 | Автоначисление после подтверждения заявки + уведомление | 3.1 | M |
| 3.3 | Реферальная ссылка и вознаграждение | 1.1, 3.2 | M |
| 3.4 | «Поделиться подборкой» и Stories | — | S |

**3.1 идёт первым, потому что сейчас счётчик мёртвый.** Программа лояльности
показывает человеку число, которое ни на что не влияет — это хуже, чем её
отсутствие: обещание, которое магазин не выполняет.

**3.3 — вознаграждение по факту подтверждённой заявки, а не по регистрации.**
Награда за приведённого пользователя — это ферма ботов ровно на следующий день.
Начисление вешается на тот же переход статуса, что и 3.2, и живёт в серверной
таблице фактов (`leads`), а не в клиентописуемых событиях.

**Себе рефералку не выписать.** Приглашённый = новый `telegram_id`, которого
раньше не было; самоприглашение и повторное приглашение уже существующего
пользователя не начисляют ничего.

**Что нужно решить владельцу до фазы:** размер вознаграждения в рублях или
баллах и потолок на пользователя. Это не техническое решение, и угадывать его
я не буду.

### Фаза 4 — Деньги и доверие (недели 7–8)

**Результат:** заявку можно оплатить, а не только «согласовать с менеджером».

| # | задача | объём |
|---|---|---|
| 4.1 | Провайдер оплаты: подключение и вебхук | L |
| 4.2 | Статус оплаты в заявке, уведомления обеим сторонам | M |
| 4.3 | Отзыв после покупки | M |

**Это единственная фаза с внешним блокером.** Подключение эквайринга упирается
в юрлицо, договор и 54-ФЗ — то есть в решение владельца, а не в код. **Решение
нужно принять к концу фазы 2**, иначе фаза 4 встанет.

**Telegram Stars по-прежнему не подходят** — они для цифровых товаров, техника
физическая, риск блокировки бота (`PATCH_1.1.md` §4). Это решение не
пересматривается без отдельной проверки политики.

**Промежуточный вариант, если эквайринга не будет к сроку:** предоплата-бронь
ссылкой, выставляемой вручную из заявки. Хуже по конверсии, но не блокирует
остальной патч.

**4.3 — отзывы считаются по фактам заявок,** то же правило, что и у social
proof: отзыв может оставить только тот, у кого есть подтверждённая заявка на
этот товар. Иначе это витрина отзывов, а не доверие.

### Фаза 5 — Контент-машина канала (недели 9–10)

**Результат:** канал наполняется без ручной работы, и каждый пост ведёт по
меченой ссылке.

| # | задача | объём |
|---|---|---|
| 5.1 | Расписание постов в тике бота | M |
| 5.2 | Автопост новинок из импорта и снижений цен | M |
| 5.3 | Вывод `admin/` из развития, перенос операций в Dexo | M |

**Нового планировщика не заводим.** В тике бота уже есть `_due(last, now,
interval)` — тот же довод, что и в патче 1.1: новая инфраструктурная деталь =
новая точка отказа и новый повод для 409 Conflict.

**Добавляешь фоновой задаче новое поле — впиши его в `REQUIRED_SCHEMA`**
(`scripts/bot_polling.py`), иначе следующий деплой даст traceback. Это уже
стреляло дважды.

**В канале только `url`-кнопки.** `web_app`-кнопка отвергает весь пост целиком —
он просто не публикуется. Все ссылки в автопостах — deep link'и с меткой
кампании из фазы 1.

## 4. Что не входит в патч 2.0

| что | почему |
|---|---|
| Мультиарендность (несколько магазинов на одном коде) | Меняет модель данных целиком. Отдельный продукт, а не фаза |
| Переписывание `admin/` | Уезжает в Dexo. Чиним только то, что мешает работать сегодня |
| Фото-оценка Trade-In через vision | Отдельный контур: загрузка, промпт, ответственность за оценку |
| Собственная доставка и склад | Магазин работает через поставщиков; склад — другая компания, не другая фича |
| A/B-тесты витрины | Нужен трафик, которого до фазы 3 не будет. Вернуться после |

## 5. Как поймём, что патч сработал

Метрики берутся из серверных таблиц фактов, не из клиентских событий.

| фаза | проверяемое утверждение |
|---|---|
| 1 | Для ≥95% пользователей, пришедших после выкладки, известен источник |
| 2 | Обновление прайса делается без единого SQL-запроса и без правки кода |
| 3 | Доля заявок со списанием баллов > 0; есть хотя бы одна заявка от приглашённого |
| 4 | Есть заявка, оплаченная онлайн, со статусом, доехавшим до обеих сторон |
| 5 | Пост в канал уходит по расписанию без участия человека, ссылка в нём меченая |

Явно **не метрика** — «стало красивее» и «добавили N фич».
